# Guide Scope And Positioning

## 1. Purpose and Scope

Use this page to understand the **scope, current detailed focus, boundaries, and positioning** of the **Win.Win AI Blind Spot Guide**.

This page answers four scope questions:

1. what the Blind Spot Guide is for;
2. what kinds of AI Blind Spot it recognises;
3. which parts of the control architecture this guide currently develops in detail; and
4. when another owner, reviewer, source, process, or companion guide is needed.

This page is a scope and governance reference. It is not the operating map of the files; use [[How To Use This Guide]] for that. It is not the canonical registry; use [[AI Blind Spot Control Map]] for the currently recognised Controls, Methods, and Accountable Routes.

---

## 2. Purpose of the Blind Spot Guide

The **Win.Win AI Blind Spot Guide** helps people manage risks that appear when an AI-supported output looks useful, clear, balanced, complete, or confident but a responsible person still needs to address something AI cannot reliably see, hold, judge, verify, authorise, or be accountable for.

AI can describe context, but it does not live inside that context. It can imitate professional reasoning, but it does not possess professional instinct. It can produce confident wording, but it cannot carry the consequences of using that wording.

This guide therefore helps readers recognise Blind Spots, select relevant recognised Controls, use available Methods, and involve accountable human routes before AI output is relied on.

---

## 3. Broad Guide Scope

AI Blind Spot is broader than unstated context.

The broad scope includes situations involving one or more of the following:

- relevant context absent from, incomplete in, or not adequately represented in the task basis;
- lived or local understanding;
- reader interpretation and recipient impact;
- judgement about materiality or consequences;
- authority and approval boundaries;
- accountability and reviewer standing;
- sufficiently independent verification;
- local or jurisdiction-specific applicability;
- professional instinct and anomaly recognition;
- bilingual, bicultural, or register meaning;
- operational memory and current operating reality;
- challenge handling and pressure to reduce justified caution;
- specialist or restricted matters that require an accountable route.

This guide may recognise Controls, Methods, and Accountable Routes across this broader scope without providing every complete discipline or implementation method.

## 4. Current Detailed Scope

**Unstated Context Control** is the current detailed Control in the **Win.Win AI Blind Spot Guide**.

Its most developed practical guidance concerns **identifying and safely eliciting unstated context**: relevant context that is absent from, incomplete in, or not adequately represented in the task basis.

Within that Control, related current-task guidance also helps readers:

- identify a possible task-basis gap;
- locate likely sources in people, approved records, both, or an unclear source;
- if current approved material already exists, retrieve the source and extract the task-relevant material;
- assess representability;
- use safe elicitation when it is suitable;
- if underlying context should not enter AI, convert only the necessary effect;
- keep context human-only if required;
- use verification or an Accountable Route if the issue cannot be responsibly resolved within the current task; and
- stop, escalate, or decline to use or record context when appropriate.

This supporting current-task guidance does not make every part of Unstated Context Control a co-equal detailed module, and it does not make every related recognised Control a detailed module.

## 5. Recognised Controls Beyond the Current Detailed Scope

This guide may **recognise and define a Control without yet explaining that Control in detail**.

The canonical registry of currently recognised Controls is maintained in [[AI Blind Spot Control Map]]. The same page defines recognised reusable Methods and Accountable Routes.

Recognition means that this guide has enough basis to name and define the safeguard and map it to relevant risks. It does not mean that a complete application framework is provided here.

If a potentially relevant safeguard, reusable method, or accountable route has not yet been recognised and defined by this guide, do not invent a canonical name merely to fill a gap. The recognised set may expand later through owner-approved development.

---

## 6. Scope Boundaries

This guide does not make AI accountable, authorised, locally situated, professionally experienced, independently verifying, or able to carry human consequences.

It does not claim that:

- supplying more context solves every Blind Spot;
- a Control is fully implemented merely because it is named in the Control Map;
- a Method transfers authority or accountability to AI;
- an Accountable Route guarantees approval or a particular outcome;
- every recognised Control, Method, or Accountable Route is required in every task;
- the currently recognised set is permanently complete;
- a prompt, source packet, elicitation answer, checklist, or AI self-review proves an output is correct, complete, authorised, safe, or fit for use.

This guide does not replace legal, regulatory, HR, privacy, financial, safeguarding, counselling, pastoral, theological, medical, technical, or other specialist processes. Use the appropriate approved process and qualified accountable person when those boundaries apply.

Full organisational-context lifecycle design, knowledge-management architecture, records-management architecture, retention and deletion frameworks, and retrieval-augmented generation implementation remain outside the current detailed scope.

## 7. Relationship with the Win.Win AI Use Case Guide

The guides are companions with different starting points.

```text
Win.Win AI Use Case Guide
= starts from the AI-supported task and gives task-specific preparation,
  prompting, review, mitigation, escalation, approval, recordkeeping,
  and workflow guidance.

Win.Win AI Blind Spot Guide
= starts from a Blind Spot concern and provides deeper risk recognition,
  Control selection, available Methods, current detailed Unstated Context Control
  guidance when relevant, and accountable routing when needed.
```

Use the **Win.Win AI Use Case Guide** when you need task-specific guidance. Use this guide when the task raises a Blind Spot that needs deeper recognition, Control selection, unstated-context work when relevant, reviewer-standing assessment, or accountable routing.

Neither guide transfers responsibility to AI. The responsible person and organisation remain accountable for the use of AI-supported output.
