# How To Use This Guide

## 1. Purpose and Scope

Use [[Start Here]] when you only need a quick entry point.

Use this page when you need to understand how the files in the **Win.Win AI Blind Spot Guide** work together. It shows how to:
- recognise an AI Blind Spot risk;
- identify relevant Controls;
- use available Methods;
- involve an Accountable Route;
- enter the detailed Unstated Context Control sequence when relevant; and
- recognise when ordinary review is not enough.

This page is the operating map of this guide. It does not:
- redefine the scope boundaries in [[Guide Scope And Positioning]];
- replace the canonical terminology in [[Glossary]]; or
- reproduce the detailed instructions in each working file.

Read it when you are learning this guide’s architecture, training reviewers, adapting this guide for an organisation, or deciding which file to open next.

---

## 2. Operating Principle

Start with the real task and the Blind Spot concern, then use only the parts of this guide needed to handle that concern responsibly.

The core architectural relationship is:

```text
AI Blind Spot risk → relevant Control(s) → applicable guidance and Method(s) → Accountable Route where required
```

Use [[Start Here]] for the practical first-use sequence. Use [[AI Blind Spot Control Map]] for the canonical Controls, Methods, Accountable Routes, and their many-to-many relationships.

Do not insert Unstated Context Control automatically between risk identification and Control selection. Use it when the risk and task show that relevant context may be absent from, incomplete in, or not adequately represented in the task basis.

AI output remains a draft, helper, or review aid. The responsible person and organisation remain accountable for what is used, sent, approved, published, relied on, or acted on.

Use [[Author and Editor Guide]] when authoring, editing, customising, localising, validating, or maintaining this guide.

|---|---|---|

## 4. Definitions and Canonical Registries

Each controlled term or canonical item has one authoritative definition in one place.

[[Glossary]] defines the core model terms, roles and standing, decision labels, and architectural concepts such as **Control**, **Method**, and **Accountable Route**. It does not independently define canonical AI Blind Spot risks or individual canonical Controls, Methods, or Accountable Routes.

[[AI Blind Spot Risk Library]] defines the canonical AI Blind Spot risks and provides the risk-specific recognition and handling guidance for them.

[[AI Blind Spot Control Map]] defines the individual canonical Controls, Methods, and Accountable Routes and documents their many-to-many relationships, including risk mappings.

This page explains where those authorities sit; it does not reproduce their definitions or relationship registries.
