# Organisational Context Handling

## 1. Purpose and Scope

Use this page as a **short orientation for organisational context** when a possible task-basis gap has been identified. It helps a reviewer think about three questions before opening the detailed handling guidance:

1. **What may be missing?**
2. **Where may it exist?**
3. **Can it be represented clearly and safely enough for AI use?**

Use [[Unstated Context Control]] for the detailed current-task handling sequence. This page does not reproduce that sequence.

It also does not provide a complete organisational-context lifecycle, knowledge-management, records-management, retention, retrieval, or RAG framework.

---

## 2. What may be missing

Look for context about the organisation, task, people, audience, authority, decision, history, timing, language, preferences, consequences, or operating environment.

Here, **unstated context** means relevant context that is absent from, incomplete in, or not adequately represented in the task basis.

---

## 3. Where it may exist

Use this source-location check:

- people;
- approved records;
- both;
- unclear.

A context item may be known by people and recorded at the same time. If a current approved record may contain the answer, use [[Source Packet Add-On]] before asking people to recreate it.

---

## 4. Representability

Consider whether the relevant context is:

- clearly expressible;
- partly expressible;
- difficult to articulate;
- unsafe or inappropriate to state; or
- not fully expressible for AI use.

Representability helps determine the handling route. It does not by itself decide whether the context is reliable, authorised, material, or suitable to preserve.

---

## 5. Worked example

AI is drafting an event plan, but an experienced coordinator remembers an evening-access constraint that is missing from the task basis.

1. Check whether a current approved venue record confirms the constraint.
2. If the record confirms it and the minimum fact is safe and necessary, use that approved fact in the task basis.
3. If underlying staffing detail should remain outside AI, keep that detail human-only and use only the safe effect needed for drafting or review.
4. If it is unclear whether the constraint is current or who has authority to decide, use the appropriate verification or accountable route.

This example illustrates the orientation only. Use [[Unstated Context Control]] for the full handling choices.

---

## 6. Where to continue

- Use [[Unstated Context Control]] for detailed source, representability, safe-conversion, human-only, verification, stopping, and escalation guidance.
- Use [[Elicitation Techniques]] when a suitable person may carry relevant context implicitly and a focused question is safe and permitted.
- Use [[Source Packet Add-On]] for approved-source retrieval and task-relevant extraction.
- Use [[Organisational Memory Habit]] and [[Templates/Exception Note Template]] only when a safe, reliable, reusable lesson may need separate preservation.
