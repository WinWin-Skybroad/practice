# Organisational Memory Habit

## 1. Purpose and Scope

Use this page when a current task has revealed a **safe, reliable, reusable lesson that should not be lost** before the next responsible person performs a similar task. It provides a small preservation habit and points to the optional exception-note template.

The page supports safe preservation after the current task; it is not part of the seven minimum current-task handling routes and does not make the source packet a long-term organisational record.

It does not provide a complete organisational-memory, knowledge-management, records-management, retention, deletion, access-control, or RAG framework.

---

## 2. The small habit

When a useful exception, warning, local practice, operational lesson, or relationship-sensitive context is discovered during AI preparation or review, first classify whether it is safe and appropriate to preserve.

After classification and permission, record approved reusable context promptly enough that the detail is not lost. The aim is normally a short, safe, practical note, not the full underlying history.

Use [[Templates/Exception Note Template]] if the context is a reusable exception, local practice, prior decision, operational lesson, relationship-sensitive warning, or other reusable context that can be recorded safely by the right owner.

---

## 3. Safe note pattern

Use a short pattern such as:

```text
When [trigger or situation] happens, check [approved source, person or function] before [action, output or approval].
```

Safe generalised examples:

```text
Before sending a broad announcement about a role change, check that affected people have been told directly first.
```

```text
Before using last year’s event checklist for this venue, check access and setup notes because lift availability affected timing.
```

```text
When an invoice approval exception appears to apply, check the approved finance exception route before drafting approval wording.
```

---

## 4. Where to record it

Use the approved place the organisation already uses for that type of information, such as:

- an internal procedure page;
- an event checklist;
- an approved supplier note;
- a controlled exception record;
- a restricted policy or decision note;
- a reviewer note held by the accountable owner.

Do not create a public or widely shared note for private or sensitive matters.

---

## 5. What not to preserve in ordinary notes

Do not store sensitive personal data, safeguarding details, counselling information, disciplinary details, private relationship history, complaints, investigations, or unverified allegations in ordinary shared notes.

Do not create a shadow HR, pastoral, safeguarding, disciplinary, counselling, complaint or investigation record under the label of organisational memory.

Use the organisation’s proper restricted process and escalate to an accountable owner.

---

## 6. Scope Boundary

Full organisational-context lifecycle design, records architecture, preservation system, enterprise retrieval model, RAG system, retention schedule and metadata model are outside the current detailed scope.

---

## 7. Practical rule

Record only enough to help the next responsible person avoid rediscovering the same issue.

Preserve the note only if it is:
- accurate;
- necessary;
- permitted;
- current;
- safe;
- sufficiently reliable;
- reusable;
- appropriate to preserve; and
- assigned to an accountable owner and approved location.
