# Source Packet Add-On

## 1. Purpose and Scope

Use this page when the **task basis may be incomplete before prompting or review**, especially if a current approved source may already contain relevant information that should be retrieved and extracted rather than recreated from memory.

This add-on strengthens the source packet by checking approved sources, intended use, audience, exclusions, authority boundaries, review basis, and relevant unstated-context needs. It supports the Source Packet Check Method and Approved Record Retrieval and Extraction Method used by several Controls.

It does not create a complete records, metadata, preservation, retention, deletion, retrieval, or RAG framework, and a strong source packet does not replace human review, verification, authority, or specialist judgement.

## 3. Check for approved records

Before asking people to recreate context, first check whether a current approved record exists.

| Question | Notes |
|---|---|
| What approved record may already contain the answer? |  |
| Who owns or approves that record? |  |
| Has the current approved source been retrieved? |  |
| Has the relevant part been properly extracted for this task? |  |
| Is the record current enough for this task? |  |
| Is the record permitted for this use? |  |

If the approved material exists, retrieve the current approved source and extract only the task-relevant material. Do not force people to restate what the organisation has already approved.

---

## 4. Unstated-context add-on

Check whether the task basis is missing or thin on:

- local practice;
- unwritten exceptions;
- prior decisions;
- relationship history;
- recent events;
- audience sensitivity;
- authority signals;
- materiality thresholds;
- local requirements;
- language, tone or register;
- operational memory;
- trust, reputation or organisational politics.

Do not use elicitation automatically before relying on AI. Use elicitation only if the context is likely to be held implicitly by a suitable person and the question is safe, permitted, and within standing.

---

## 5. What not to put into AI

Do not place the following into ordinary AI tools unless the organisation has an approved safe process and the use is necessary, permitted, current and safe:

- private personal data;
- safeguarding details;
- counselling information;
- disciplinary details;
- sensitive legal or regulatory facts;
- confidential relationship history;
- unverified allegations;
- material reserved for an authorised owner.

Use safe conversion, human-only handling, verification, responsible-owner review, specialist review, or escalation as needed.

If underlying details are sensitive or unsuitable for AI:
- keep those details outside the AI tool; and
- use an authorised human reviewer to apply only the necessary safe effect.

Add context to AI only if it is accurate, necessary, permitted, current, and safe. Otherwise use safe conversion, human-only handling, a sufficiently independent verification route, accountable or specialist review, or escalation.

---

## 6. Scope Boundary

The source packet is a current-task control. It is not automatically the long-term organisational record and does not replace [[Organisational Context Handling]], [[Organisational Memory Habit]], restricted records processes, or accountable owners.

---

## 7. Practical rule

```text
Have we given AI the right source material, and have we kept sensitive review-only context out of the AI tool?
```
