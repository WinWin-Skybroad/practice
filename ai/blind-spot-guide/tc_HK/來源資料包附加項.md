# 來源資料包附加項

## 1. 目的及範圍

當 **提示或審核前的任務依據可能不完整** 時使用本頁，尤其是目前已批准來源可能已包含相關資訊，而應檢索及提取該資訊，而不是依賴記憶重新建立。

本附加項透過核對已批准來源、預定用途、受眾、排除事項、權限邊界、審核依據及相關未明說語境需要，強化來源資料包。它支援多項控制所使用的來源資料包核對方法，以及獲批准紀錄檢索及擷取方法。

它不建立完整的紀錄、中繼資料、保留、保存期、刪除、檢索或 RAG 框架；而且強大的來源資料包也不取代人工審核、核實、權限或專門領域判斷。

## 3. 核對已批准紀錄

在要求人重新建立語境前，先檢查目前已批准紀錄是否存在。

| 問題 | 備註 |

| 是否已檢索目前已批准來源？ |  |
| 是否已為本任務妥善擷取相關部分？ |  |
| 該紀錄對本任務而言是否足夠現時有效？ |  |
| 該紀錄是否獲允許用於此用途？ |  |

如已批准材料存在，檢索目前已批准來源，並只擷取與任務相關的材料。不要迫使人重新陳述機構已經批准的內容。

---

## 4. 未明說語境附加項

核對任務依據在以下方面是否缺失或不足：

- 本地做法；
- 未成文例外；
- 先前決定；
- 關係歷史；
- 近期事件；
- 受眾敏感度；
- 權限訊號；
- 重要性門檻；
- 本地要求；
- 語言、語氣或語域；
- 營運記憶；
- 信任、聲譽或機構政治。

不要在依賴人工智能前自動使用引導提取。只有當合適的人可能隱含地掌握相關語境，而且問題安全、獲允許並在其適任性範圍內時，才使用引導提取。

---

## 5. 不應輸入人工智能的內容

除非機構有已批准的安全流程，而且該用途必要、獲允許、現時有效及安全，否則不要把以下內容放入普通人工智能工具：

- 私人個人資料；
- 安全保障細節；
- 輔導資料；
- 紀律細節；
- 敏感法律或法規事實；
- 機密關係歷史；
- 未經核實的指控；
- 保留給獲授權負責人的材料。

按需要使用安全轉換、僅由人處理、核實、責任負責人審核、專門領域審核或升級處理。

如底層細節敏感或不適合人工智能：
- 把這些細節留在人工智能工具之外；以及
- 由獲授權的人工審核者只套用必要的安全影響。

只有在語境準確、必要、獲允許、現時有效及安全時，才把它加入人工智能。否則，使用安全轉換、僅由人處理、具足夠獨立性的核實路徑、須問責或專門領域審核，或升級處理。

---

## 6. 範圍界線

來源資料包是目前任務控制。它不會自動成為長期機構紀錄，也不取代 [[機構情境處理]]、[[機構記憶習慣]]、受限制紀錄流程或須問責的負責人。

```text
我們是否已向人工智能提供正確的來源材料，並把只供審核的敏感語境留在人工智能工具之外？
```
