# RAG 知识库就绪度评估

**在构建从您的文件回答的人工智能之前**

> [!quote] 用途：  
> RAG（检索增强生成）让人工智能通过搜索您自己的文件来回答问题，而非仅依赖其训练数据。这听起来很强大——确实可以如此。但仅当您的文件已整理、最新、有组织且法律上允许使用时，它才有效。  
> 本评估帮助您在开始构建之前确认您是否已准备就绪。

**本评估用途：** 针对任何依赖从文件库搜索和检索的人工智能使用场景的结构化就绪度检查。

**本评估非：** 技术 RAG 实施指南或保证通过评分即代表您的系统将正确运作。文件就绪度可降低幻觉风险——但不消除它。

---

## 1. 什么是 RAG 以及为何就绪度重要？

在标准人工智能对话中，模型依赖其训练数据。在 RAG 系统中，模型首先从您提供的文件库检索相关内容，然后使用该内容生成答案。

这意味着：**您答案的质量受限于您文件的质量。**

建立在坏文件上的 RAG 系统会产生坏答案——且充满自信。与简单搜索不同，RAG 不向您显示原始文件。它综合它们。错误在出问题前是不可见的。

**常见 RAG 失败模式：**
- **过时政策** — 用去年的规则回答客户
- **空白繁体中文文件** — 扫描的中文返回空白；人工智能捏造答案
- **格式缺口** — 混合文件格式可能导致检索缺口，使部分内容无法被人工智能找到
- **个人信息泄露** — 敏感信息最终嵌入人工智能回应
- **矛盾答案** — 矛盾文件产生矛盾答案
- **缺失来源** — 当正确来源缺失于文件库时，人工智能仍自信回答

---

## 2. 评估结构

本评估有四个关口。任何关口的失败意味着在构建 RAG 系统之前必须修复该关口的工作。

| 关口 | 检查内容 | 失败影响 |
|------|----------|----------|
| **关口 1 — 法律许可** | 您是否允许在人工智能系统中使用这些文件？ | 数据泄露、违反《个人资料（私隐）条例》、信任损害 |
| **关口 2 — 文件质量** | 文件是否机器可读、最新、准确且一致？ | 幻觉、缺口、错误答案 |
| **关口 3 — 知识架构** | 文件库是否组织良好以便人工智能检索正确内容？ | 检索失败、无关答案 |
| **关口 4 — 治理** | 是否有控制措施使系统随时间保持准确和有界限？ | 漂移、不受控范围、未检测错误 |

> [!warning] 若任何关口未能通过，必须先解决该关口的问题，然后才可继续构建。切勿在关口问题尚未解决的情况下，试点任何 RAG 系统。

---

## 3. 就绪度关口 — 四个顺序检查

按顺序完成每个关口。任何关口的失败都是停止条件 — 在进入下一个关口之前解决它。如果关口 1 有尚未解决的项目，不要进入关口 2。关口这样设计是有意的：构建后发现法律或数据许可问题比现在发现成本高得多。

### G1 关口 1 — 法律许可

回答每个问题。此关口中任何单一的「否」或「不确定」意味着： **停止并在继续前解决。**

#### G1.1 数据收集目的
- [ ] **兼容目的** — 文件创建目的与人工智能处理兼容
- [ ] **目的阐述** — 我们能解释为何人工智能处理与原始收集目的一致

> [!warning] 《个人资料（私隐）条例》原则 3：  
> 为某一目的收集的个人信息不得在未经同意的情况下用于实质上不同的目的。使用人力资源档案、客户记录或牧养笔记为人工智能问答系统提供动力几乎肯定是需要新鲜评估的新目的。

#### G1.2 个人信息评估
- [ ] **已识别个人信息** — 已识别包含姓名、香港身份证号、联系方式、健康、财务或人力资源信息的文件
- [ ] **已排除或正当化** — 个人信息已排除于文件库之外，或包含已确认法律上许可并记录
- [ ] **已排除牧养记录** — 文件库中无受益人记录、辅导笔记、祈祷事项或敏感披露

#### G1.3 访问控制
- [ ] **用户仅见许可内容** — RAG 系统仅展示查询用户许可的文件
- [ ] **无跨角色泄露** — 无员工检索不同团队或角色文件的风险
- [ ] **受保护敏感文件** — 人力资源、财务和牧养文件已排除或位于访问控制之后

#### G1.4 工具和供应商条款
- [ ] **已审阅供应商条款** — 已审阅人工智能工具供应商的服务条款和数据处理政策
- [ ] **理解训练条款** — 工具是否保留、索引或训练上传的文件
- [ ] **可接受的数据驻留** — 工具的数据驻留条款对此内容类型可接受

#### G1.5 第三方内容权利
- [ ] **已确认拥有权** — 我们拥有或有权利使用所有文件进行人工智能处理
- [ ] **已排除版权内容** — 无第三方版权内容未经检查许可条款
- [ ] **允许政府文件** — 在其许可条款内使用

#### G1.6 保密性和敏感性
- [ ] **已排除机密** — 无标注为机密或受限的文件除非另行批准
- [ ] **已排除商业秘密** — 无商业敏感信息或定价数据
- [ ] **已排除法律特权** — 已排除法律特权通讯

#### 关口 1 结果：通过 / 失败

> [!warning] 关口 1 是硬性停止：  
> 如果任何项目以上是「否」或「不确定」— 在解决前不要进入关口 2。  
> 构建后发现法律或数据许可问题比现在发现成本高得多。

### G2 关口 2 — 文件质量

#### G2.1 机器可读性

| 文件类型 | 可读性 | 行动 |
|------|----------|----------|
| 打字 Word / Google Docs | ✅ 通常可读 | 验证字符编码 |
| 打字 PDF（数字文本） | ✅ 通常可读 | 抽查文本提取 |
| 扫描 PDF — 英文 | ⚠️ 取决于光学字符识别 (OCR) 质量 | 测试提取；如需则应用 OCR |
| 扫描 PDF — 繁体中文 | 🔴 通常不可读 | 必须先转换为数字文本 |
| 图像文件（文件的 JPG、PNG） | 🔴 作为文本不可读 | 必须 OCR 并验证 |
| WhatsApp / 消息导出 | ⚠️ 混合质量 | 纳入文件库前先整理和重新格式化 |
| 音频/视频转录 | ⚠️ 取决于转录质量 | 纳入文件库前先验证准确性 |

- [ ] **仅数字文本** — 所有文件为机器可读文本格式；无扫描图像
- [ ] **按需转换** — 表格、多栏布局和格式化文件提取为纯文本
- [ ] **已测试每个文件** — 提取代表性部分并验证为准确
- [ ] **已测试繁体中文可读性** — 已测试每个繁体中文文件的文本可选择性
- [ ] **已转换扫描繁体中文** — 所有扫描繁体中文文件转换为机器可读文本并验证
- [ ] **已移除不可提取** — 已移除无法可靠提取的文件

**香港特定测试：** 对于任何繁体中文文件 — 尝试选择和复制一个段落。如果它复制为可读字符，它可能是机器可读的。如果它选择为单个图像块，使用前需要 OCR 预处理。

#### G2.2 及时性和准确性
- [ ] **每个文件有版本日期** — 或最后审阅日期
- [ ] **已审阅旧文件** — 已检查超过 [设置门槛] 的文件准确性
- [ ] **已移除过时内容** — 已更新或移除取代的政策、旧员工或过时程序
- [ ] **存在更新流程** — 政策变更时更新文件库的流程
- [ ] **每个文件有命名负责人** — 负责更新
- [ ] **已抽查样本** — 已检查 3–5 个文件：每个文件 3–5 个具体事实已针对当前真实来源验证
- [ ] **事实匹配现实** — 姓名、日期、费用、政策和程序匹配当前现实状态
- [ ] **无冲突版本** — 或如果存在，已明确识别正确版本
- [ ] **已检查 OCR 错误** — 已检查扫描或 OCR 处理文件的提取错误

> [!warning] 陈旧文件是无声幻觉来源：  
> RAG 系统不知道文件过时。它会自信地用去年的政策回答。在构建之前为每个文件添加日期标记并设置审阅周期。

#### G2.3 完整性
- [ ] **已映射问题** — 前 20 个常见问题已映射到具体文件：完全覆盖 / 部分覆盖 / 未覆盖
- [ ] **存在关键政策** — 不仅部分覆盖
- [ ] **已记录例外** — 边缘情况和升级路径已记录，不仅标准流程
- [ ] **缺口门槛** — 如果超过 25% 的目标问题未覆盖，文件库有导致人工智能猜测的缺口

#### G2.4 来源
- [ ] **已知来源** — 每个文件有已知来源；非「从某处下载」
- [ ] **命名负责人** — 每个文件有命名负责人
- [ ] **已追踪转换** — 扫描、OCR 或重新格式化的文件仍可追踪回原始文件

#### G2.5 一致性和冲突
- [ ] **文件间一致** — 多个文件中相同主题覆盖一致
- [ ] **已解决矛盾** — 已调和矛盾文件或指定一个版本为权威

> [!note] 真理层级：  
> 如果两个文件对同一问题给出不同答案，提前建立哪一个是权威来源。无此，人工智能将产生矛盾答案取决于检索哪个区块。

#### G2.6 范围和完整性
- [ ] **覆盖真实问题** — 文件库覆盖用户实际会问的问题

> [!note] 实用测试：  
> 取 10–20 个人工智能系统需要回答的真实问题。答案能否在您汇编的文件中找到？如果超过 3/10 无法从您的文件回答 — 文件库对此使用场景不完整。

- [ ] **无幻觉缺口** — 无明显缺口导致人工智能无内容检索并可能幻觉
- [ ] **范围有界限** — 已决定系统将回答什么和不回答什么
- [ ] **范围外后备** — 范围外问题有定义的后备回应

#### 关口 2 结果：通过 / 失败

> [!warning] 关口 2 关键洞察：  
> 大多数组织在关口 2 发现其文件问题 — 而非技术设置。  
> 构建前整理文件，远比上线后修正错误输出更省时。

### G3 关口 3 — 知识架构

#### G3.1 相关性和范围
- [ ] **使用场景聚焦** — 文件库仅包含和使用场景有直接联系的文件；非共享存储空间中的所有内容
- [ ] **已排除噪音** — 已移除无关或边缘文件
- [ ] **书面范围** — 包含什么和不包含什么，书面定义

**相关性测试：** 取 10–20 个人工智能系统需要回答的真实问题。答案能否在您汇编的文件中找到？如果超过 3/10 无法回答 — 文件库对此使用场景不完整。

#### G3.2 结构和可检索性
- [ ] **逻辑分类** — 按主题、部门或文件类型
- [ ] **标题和结构** — 有意义的标题；非一个长未划分文本块
- [ ] **有用的元数据** — 每个文件有标题、负责人、日期、主题、文件类型
- [ ] **可过滤** — 系统可按日期、部门或文件类型过滤
- [ ] **已拆分长文件** — 在逻辑边界拆分以便检索浮现正确部分
- [ ] **存在主索引** — 文件库内容列表或索引
- [ ] **已移除重复** — 已合并重复或近似重复版本

#### G3.3 区块设计和检索测试
- [ ] **完整思想** — 区块大小包含完整思想；非切割中途句子或中途政策
- [ ] **每个区块来源元数据** — 文件名称、部分、日期和版本
- [ ] **尊重繁体中文边界** — 对于繁体中文内容，区块尊重繁体中文句子和段落边界
- [ ] **已测试代表性问题** — 已编写和测试 10–20 个代表性用户问题
- [ ] **浮现正确文件** — 检索系统为代表性问题浮现正确文件
- [ ] **已测试范围外** — 已测试至少 5 个范围外问题；系统适当拒绝

#### G3.4 检索质量测试
- [ ] **答案正确** — 已检查测试答案：答案是否正确？是否引用正确来源？
- [ ] **检索正确来源** — 正在检索相关来源，非无关文件
- [ ] **已测试「我不知道」** — 系统在不知道时如此说；不幻觉
- [ ] **已识别坏结果类型** — 已识别和理解返回坏结果的查询类型

#### G3.5 访问控制（《个人资料（私隐）条例》对齐）
- [ ] **尊重权限** — 检索尊重用户权限；用户仅见许可文件
- [ ] **已排除或编辑敏感** — 索引前
- [ ] **审计追踪** — 已记录查询和检索区块用于《个人资料（私隐）条例》问责

#### G3.6 语言和双语处理
- [ ] **已决定语言** — 系统是否用英文、繁体中文或两者回应
- [ ] **文件库语言匹配** — 预期查询语言
- [ ] **双语一致性** — 对于双语系统：两种语言表达相同政策一致

#### 关口 3 结果：通过 / 失败

### G4 关口 4 — 治理

#### G4.1 输出验证
- [ ] **已引用来源** — 系统为每个声明引用来源；用户可检查来源部分
- [ ] **已标记不确定性** — 当系统不确定时，它如此说而非猜测
- [ ] **反馈流程** — 用户标记他们认为错误答案的清晰流程

#### G4.2 人工审核
- [ ] **命名审核者** — 负责在高风险使用前审核人工智能回应的人
- [ ] **外部使用前审核** — 任何 RAG 输出用于外部通讯或正式决策前需要人工审核
- [ ] **已披露人工智能** — 用户知道他们与人工智能互动，非人类

#### G4.3 持续维护
- [ ] **命名文件库负责人** — 负责保持文件最新
- [ ] **已定义审阅节奏** — 文件将多久检查和更新一次？
- [ ] **更新流程** — 政策变更时，更新相关文件的清晰流程
- [ ] **已归档过时** — 已归档或移除过时文件；非留在上线文件库
- [ ] **变更记录** — 任何给定时间上线的文件库版本的版本记录

#### G4.4 范围边界
- [ ] **范围声明** — 系统有清晰定义范围：它将回答什么和不回答什么
- [ ] **优雅拒绝** — 范围外问题产生拒绝和转介到人类
- [ ] **始终范围外** — 系统不尝试回答：牧养关怀、医疗、法律、受益人资格或人力资源决策
- [ ] **已告知用户** — 已告知用户系统能做什么和不能做什么

#### G4.5 监控和错误回应
- [ ] **用户标记** — 用户报告错误答案的机制
- [ ] **调查流程** — 调查报告错误的定义流程
- [ ] **暂停规则** — 在什么条件下系统将离线审阅？
- [ ] **事件后学习** — 已记录并反馈到文件改进
- [ ] **问题记录** — 定期审阅记录了的问题和答案的流程
- [ ] **标记回应** — 对标记错误答案行动的流程，包括文件库更新
- [ ] **升级路径** — 如果发生严重错误已定义

#### 关口 4 结果：通过 / 失败

## 5. 红 / 琥珀 / 绿决策

基于所有四个关口：

| 状态 | 含义 | 决策 |
|------|------|------|
| 🟢 **绿** | 所有关口项目通过 | 进入试点 — 首先与有限观众构建和测试 |
| 🟡 **琥珀** | 具体项目失败 — 已识别缺口 | 修复已识别缺口；构建前重新评估 |
| 🔴 **红** | 关口 1 失败，或多个关口 2/3 项目失败 | 不要进入 — 首先解决根本原因 |

**琥珀或红的最常见原因：**
- **无文件负责人** — 关口 2 / 关口 4
- **无版本日期** — 关口 2
- **多个版本** — 无清晰当前流通的副本，关口 2
- **文件库中的个人信息** — 无法律审阅，关口 1
- **无 OCR 的扫描繁体中文** — 关口 2
- **自信错误答案** — 当来源未覆盖问题时系统回答，关口 4

## 6. 正式上线前的香港特定检查清单

- [ ] **已转换扫描繁体中文** — 所有扫描繁体中文文件已转换和验证
- [ ] **《个人资料（私隐）条例》原则 3** — 已确认所有个人信息文件的合规性
- [ ] **已排除牧养记录** — 文件库中无牧养、辅导或敏感事工记录
- [ ] **已测试双语** — 已用英文和繁体中文查询测试检索
- [ ] **已验证香港规例** — 香港规例内容在包含前已针对官方来源验证
- [ ] **资助者人工智能政策** — 如果包含资助相关文件，资助者已确认人工智能处理允许
