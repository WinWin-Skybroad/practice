# 人工智能代理审批检查清单

**在人工智能可以单独行动之前**

> [!note] **适用对象：**  
> 技术负责人、运营经理及考虑使用可采取自动化行动的人工智能工具的信息技术能力职员。大多数刚开始使用人工智能的教会及小型组织暂时不需要此文件。如您仅使用人工智能起草文本供人工审核，请先从 [[3P 框架海报]] 及 [[人工智能安全检查清单 - 工作版]] 开始。

> [!quote] 关键区别：  
> 标准人工智能工具只作回应。但人工智能代理会作行动。  
> 在您赋予人工智能发送消息、更新记录、预约会议、提交表格或进行购买的能力之前 — 您需要不同的控制措施。此检查清单就是这些控制措施。

**本检查清单用途：** 针对任何可采取行动的人工智能系统（不仅仅是生成文本）的结构化审批关口。

**本检查清单非：** 通过评分即代表代理安全或将正确运作的保证。代理式人工智能引入了标准文本生成所没有的真实风险。此检查清单降低这些风险 — 但不消除它们。

---

## 1. 代理与标准人工智能使用的区别

标准人工智能使用：您提供输入 → 人工智能生成文本 → 人手阅读并决定如何处理。

人工智能代理：人工智能可采取行动 — 发送邮件、更新记录、预约会议、提交表格，或发布社交媒体 — 通常每个步骤有限或无需人手批准。

**组织环境中代理式人工智能的示例：**
- **自动回复邮件** — 自动阅读并发送回复
- **自动预约** — 代表您预约会议室或预约
- **记录更新** — 根据对话更新客户管理系统、电子表格或数据库
- **自动广播** — 自动发布社交媒体或发送消息广播
- **表格提交** — 无需人手确认即可提交表格、申请或订单
- **多步骤工作流程** — 研究 → 起草 → 发送 → 跟进

**为何代理需要不同的控制措施：** 使用标准人工智能工具时，您在任何事情发生前会看到输出。使用代理时，行动可能已在您注意到之前采取。错误可能在多个步骤中传播。逆转它们可能困难或不可能。

> [!important] 首先询问此问题：  
> 此工作流程能否透过设计良好的提示词及人手点击发送来实现 — 而非完全自主的代理？  
> 许多看似需要代理的工作流程，透过良好的提示词及人工审核机制同样运作良好。  
> 如是 — 使用更简单的方法。代理会放大价值与风险。

## 2. 四个代理风险维度

| 维度 | 问题 | 为何重要 |
|------|------|----------|
| **可逆性** | 如代理犯错，能否逆转？ | 发送的消息无法撤回。删除的记录可能无法恢复。 |
| **影响规模** | 如出错，会影响多少人或系统？ | 代理发送邮件给一个人与发送给整个会众的区别。 |
| **可见性** | 您能否看到代理做了什么、何时、为何？ | 如无审计追踪（记录人工智能做了什么、何时、为何 — 以便调查错误），错误在后果出现前不可见。 |
| **授权** | 是否有人明确批准每种行动类型？ | 代理不应采取其操作者未有意识批准的行动。 |

## 6. 强制人手批准触发条件

以下行动类型必须始终要求明确人手批准后方可执行，无论代理的置信度如何：

- [ ] **外部通讯** — 邮件、消息、通知或社交媒体
- [ ] **财务记录** — 交易、发票或付款的修改
- [ ] **人员记录** — 人员、人力资源或成员记录的更新
- [ ] **获取或福利** — 任何影响人员资格、关顾或获取的行动
- [ ] **不可逆转行动** — 发送邮件、删除记录或提交表格
- [ ] **高成本错误** — 声誉、财务、法律或关系风险

## 7. 失败模式分析

在部署前，识别此特定代理最可能的失败模式。

| 失败模式 | 描述 | 风险等级 | 缓解措施 |
|----------|------|----------|----------|
| **提示词注入** | 文件中的恶意内容指示代理采取意外行动 | 中–高 | 净化输入；限制代理读取内容；行动前验证输出 |
| **目标误解** | 代理以意外方式解释模糊指令 | 中 | 编写精确、有界限的指令；部署前测试边缘情况 |
| **级联错误** | 多步骤工作流程中的早期错误向下游传播 | 高 | 在步骤间添加人手检查点 |
| **范围漂移** | 代理访问超出其预期范围的数据或系统 | 高 | 应用最小权限：仅授予具体所需的访问 |
| **幻觉行动** | 代理捏造其认为已获授权的决策 | 中 | 记录所有行动；实施回滚（逆转人工智能所为）；要求人工审核日志 |
| **过度自信** | 代理在无不确定性机制的情况下以低质量输出继续 | 中 | 内建不确定性门槛；低于门槛时要求人工审核 |

**针对您的特定代理 — 识别最可能的 3 种失败模式：**

| 失败模式 | 可能性？ | 如发生有多严重？ | 计划的缓解措施 |
|----------|----------|----------------|----------------|
| | 高 / 中 / 低 | 高 / 中 / 低 | |
| | 高 / 中 / 低 | 高 / 中 / 低 | |
| | 高 / 中 / 低 | 高 / 中 / 低 | |

## 9. 试点设计

代理式人工智能应始终在更广泛部署前从有界限的试点开始。

| 字段 | 您的答案 |
|------|----------|
| **试点范围** | 将测试哪些具体行动子集？ |
| **试点环境** | 真实数据/真实系统，或测试环境？ |
| **试点持续时间** | |
| **人手监督** | 人手将如何监控代理的行动？ |
| **成功标准** | 成功的试点是什么样子？ |
| **停止标准** | 在何种条件下将停止试点？ |
| **扩展前签署** | 谁必须批准从试点转向更广泛使用？ |

## 10. 禁止的代理用途 — 始终超出范围

- [ ] **牧养通讯** — 信仰、危机或辅导消息：仅限牧师或负责人
- [ ] **人力资源决策** — 雇佣、纪律、薪酬或绩效：绝不由代理执行
- [ ] **财务承诺** — 承诺资金、批准开支或启动付款：需人手批准
- [ ] **法律提交** — 提交、递交或回应法律或监管文件：绝不由代理执行
- [ ] **受益人决策** — 任何服务或福利的资格、获取或优先次序：绝不由代理执行
- [ ] **健康通讯** — 提供、推荐或根据健康相关信息行动：绝不由代理执行
- [ ] **大量个人信息** — 汇出、删除或转移大量个人信息：需明确人手授权

## 11. 受保护工作流程模式

受保护工作流程在正确位置内建人手检查点：

```
受保护工作流程模式

步骤 1：代理收集信息/研究/起草
        |
步骤 2：[人手检查点] — 人工审核代理计划或草稿
        | 已批准
步骤 3：代理执行低风险步骤（例如创建内部草稿）
        |
步骤 4：[人手检查点] — 人手在任何外部行动前审核
        | 已批准
步骤 5：代理执行 或 人手执行外部行动
        |
步骤 6：代理记录行动并向人手确认
```

**最低所需检查点：**
- **外部发送前** — 任何外部通讯
- **数据更改前** — 生产系统中任何数据修改
- **财务行动前** — 启动任何财务行动
- **意外情况** — 当代理遇到超出范围的情况时

## 13. 香港特定考虑

- [ ] **《个人资料（私隐）条例》原则 3** — 如代理处理个人信息，已评估合规性

## 14. 给组织的代理备注

对于大多数组织，近期有意义的人工智能代理使用案例是：
- **会议转录** — 摘要并由人工审核输出
- **邮件草稿生成** — 由查询触发；人手批准后发送
- **文件问答** — 有需要时可交人手跟进

完全自主的代理 — 无需每步人手批准即可发送通讯、更新记录或做出决策的代理 — 有更显著的风险，通常不适合没有专职信息技术治理能力的组织作尝试。

**原则：** 从解决真实问题的最简单方案开始。许多看似需要代理的工作流程，透过设计良好的提示词及人手点击发送同样运作良好。
