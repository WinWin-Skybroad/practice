# 人工智能幻觉防御指南

**如何捕捉自信错误与虚构细节**

> [!quote] 核心原则：  
> 将人工智能视为起草引擎，而非真相引擎。  
> 人工智能不知道它何时出错。它会以同样自信的语气产生错误答案与正确答案。  
> 防御幻觉不是为了减少对人工智能的信任——而是为了知道在何处以及如何检查。  
>  
> **流畅不等于正确**。

**本指南用途：** 建立习惯，在人工智能错误造成伤害前捕捉它们。

**本指南非：** 遵循这些步骤就能消除人工智能错误的保证。人工智能系统不提供保证答案——它们预测最可能的内容，这意味着即使做法良好，错误仍可能发生。人工审核始终是必需的。

---

## 1. 什么是幻觉？

人工智能幻觉是指模型产生 **事实错误、虚构或误导性的输出——但以自信的语气陈述**。

这不是将来会被修复的技术错误。这是人工智能系统运作的结构性特征：它们的设计目的是生成看似合理、逻辑连贯且令人信服的内容，而非用来可靠地验证这些内容是否真正正确。一个行文流畅的答案与一个错误的答案，外观上可能完全一样。

### 为何会发生？

| 原因 | 通俗解释 |
|------|----------|
| **训练数据缺口** | 模型从未接受过特定事实的训练——因此它填入看似合理的内容 |
| **无实时知识** | 大多数模型有知识截止日期；该日期后变更的事实可能错误 |
| **自信外推** | 模型扩展它识别的模式，即使不应该如此 |
| **提示词模糊** | 模糊问题产生模糊——且可能虚构——的答案 |
| **长对话记忆限制** | 在长对话中，人工智能可能失去对早期细节的追踪，后来与之前所说矛盾 |
| **检索失败（RAG）** | 在文件问答系统中，如果检索到错误来源，答案就建立在错误基础上 |

**幻觉不是：**
- **不诚实**——人工智能没有说谎
- **模型故障**——即使强大模型也会发生
- **仅限较弱人工智能**——所有现行模型都可能幻觉

**幻觉也是：**
- **错误摘要**——对真实文件
- **虚构引用**——不存在的参考文献
- **过时事实**——以现在时态陈述
- **遗漏例外条款**——关键的限制或例外条件被省略，从而改变原意
- **无依据的自信**——尤其在小众或近期主题上

> [!important] 人工智能工具的设计目的是生成回应，而非承认缺少完整背景与情境。与人类专业人士不同——当被问及超出其专业能力范围的问题时，他们会感到不确定——人工智能工具没有任何内部信号告诉它应该停下来并请求澄清。无论是否具备足够的完整背景与情境，它都会尝试回答——而两种情况下的回答听起来会同样自信。这并非不诚实，而是这些系统运作方式的结构性特征。

> [!important] **提供足够的完整背景与情境，并验证回应是否如实反映该完整背景与情境，此责任完全属于人类。**

## 2. 为何在香港更为重要

| 香港特定风险 | 为何幻觉风险更高 |
|-------------|----------------|
| **香港法律与法规** | 人工智能训练以美/英法律为主；香港条例经常错误 |
| **繁体中文** | 高质量繁体中文训练来源较少；翻译错误无声累积 |
| **近期政策** | 训练截止日期意味着近期《个人资料（私隐）条例》指引与新法规可能错误 |
| **圣经与神学** | 人工智能可能产生看似合理但教义错误的诠释 |
| **具名香港组织** | 人工智能经常混淆相似名称或虚构细节 |
| **资助与政府表格** | 人工智能可能将海外准则应用于香港特定要求 |

## 3. 五种幻觉模式

### 模式 1 — 自信虚构
人工智能陈述特定事实——统计数据、姓名、日期、案例编号——不存在或错误。

**如何识别：** 非常具体的数字但无指明来源。  
**防御：** 搜索该具体数字。如果 60 秒内找不到原始来源，不要使用它。

---

### 模式 2 — 看似合理的引用
人工智能虚构听起来真实的学术论文、法律案例或政府文件，但并不存在。

**如何识别：** 引用格式良好但无处可寻。  
**防御：** 搜索确切标题。独立验证作者、出版商与日期。绝不引用未确认存在的来源。

---

### 模式 3 — 过时事实
人工智能陈述在训练截止日期时为真但现已不正确的内容。

**如何识别：** 以现在时态陈述法规或政策信息但无日期锚点。  
**防御：** 对于任何法规相关内容，始终在当前官方来源验证，如 www.pcpd.org.hk, www.elegislation.gov.hk。

---

### 模式 4 — 自信外推
人工智能将来自一个司法管辖区或情境的规则应用于不适用之处。

**如何识别：** 将美/英规则应用于香港情境的建议，或将企业规模指引应用于中小企业。  
**防御：** 始终检查司法管辖区。如果涉及合规，请合格专业人士参与。

---

### 模式 5 — 流畅改写错误
人工智能摘要真实文件但微妙改变含义——省略条件、误述门槛或遗漏例外。

**如何识别：** 复杂文件摘要、政策改写、法律或财务摘要。  
**防御：** 对于影响决策的摘要，将人工智能输出与来源逐节直接比较。

---

## 4. 提示词层级防御（错误发生前）

减少幻觉的最佳时机是在收到输出之前。

| 技巧 | 如何使用 | 为何有效 |
|------|----------|----------|
| **来源核对** | 「仅从我的文件回答。不使用外部知识。」 | 无法幻觉未被给予的内容 |
| **不确定性提示** | 「用 [不确定] 标记不确定的声明。」 | 模型在被要求时表达不确定性 |
| **明确约束** | 「不要虚构。如果缺失，请说明。」 | 对常见幻觉类型的硬性停止 |
| **逐步推理** | 「首先列出章节。然后摘要。然后识别缺口。」 | 使推理可追踪 |
| **角色框架** | 「你是一位细心的审核员。标记不确定性，不要填补。」 | 使模型行为朝向谨慎 |

**高风险任务的安全回应模式：**
- **从提供文本**——仅摘要你给予的内容
- **分离不确定**——将不确定性与确认事实分开列出
- **选项而非决策**——你决定；人工智能提供选择
- **缺失时停止**——要求它在证据缺失时停止，而非猜测

## 5. 快速验证习惯

### 要点检查

- **步骤 1** — 选取一项 — 最具体的细节：日期、统计数据或研究名称
- **步骤 2** — 搜索它 — 仅搜索那一项
- **步骤 3** — 未找到？ — 将其余人工智能输出视为可疑

---

### 退出条款

在任何重要提示词末尾添加：

- **「我不知道」** — 「如果你不确定，请说『我不知道』而非猜测。」
- **「检查什么」** — 「列出我应该复查的 3 件事。」

---

## 6. 三检查验证系统

以导航技巧命名：你需要至少三个参考点来确认你的位置。将同样逻辑应用于人工智能输出。

### 检查 1 — 来源检查（2–5 分钟）
问人工智能： *「你这个声明的来源是什么？指明具体文件、作者、日期，以及我在何处可以找到它。」*  
对于任何进入客户文件、决策或外部沟通的内容——在原始来源验证，而非另一个人工智能或摘要。

> [!warning] 人工智能给你来源不代表来源存在：  
> 人工智能可以以与事实同样的自信幻觉引用。始终独立验证——而非再次问人工智能。

**按主题香港主要来源：**

> 如果网站没有重定向到其正式网站，你可以尝试在主要来源前加上前缀 "https://www."。例如，应该是 https://www.gov.hk 而非 gov.hk。

| 主题 | 主要来源 |
|------|----------|
| **《个人资料（私隐）条例》/ 个人信息** | pcpd.org.hk |
| **公司法** | cr.gov.hk |
| **雇佣法** | labour.gov.hk |
| **证监会法规** | sfc.hk |
| **金管局 / 银行业** | hkma.gov.hk |
| **政府政策** | gov.hk |
| **条例 / 立法** | elegislation.gov.hk |
| **香港生产力促进局人工智能指引** | hkpc.org |
| **个人资料私隐专员公署人工智能指引** | www.pcpd.org.hk/english/artificial_intelligence/index.html |
| **圣经 / 神学** | 圣经本身；你的牧师 |

---

### 检查 2 — 怀疑问题（30 秒）
问人工智能：「你这个答案中不确定的是什么？你可能哪里错了？」

**提示词模板：**
```
在我使用这个之前，告诉我：
- 你这个答案中最不确定的部分是哪些？
- 如果我告诉你 [相关情境]，什么会改变你的答案？
- 是否有香港特定规则可能使这不同？
- 哪些声明我应该验证，以及在何处验证？
```

---

### 检查 3 — 来源核对与出处检查（30–60 秒）
在提示词中直接提供来源材料。要求人工智能仅从你提供的内容工作，并指明哪个章节支持每个声明。

**使用的提示词（来源核对）：**
```
仅基于以下文本，回答以下问题。
不要添加任何不在文本中的信息。
如果答案不在文本中，请说：「我在提供的来源中找不到这个。」
在每个关键点之后，指明来源的哪个段落或章节支持它。

问题：[你的问题]
文本：[贴上你的来源文件]
```

**为何有效：** 来源核对迫使模型从你的来源工作，而非其训练。错误变成可见文件的误读——可检测——而非无形虚构。

## 7. S-A-F-E-R 框架

如果你使用人工智能进行技术或项目工作，「逐步思考」不够。你需要来源核对的框架。

使用 **S-A-F-E-R** 心智检查清单：

- **S — 来源限定** — 仅使用声明来源；无自由回忆
- **A — 承认不确定** — 迫使人工智能说「我不知道」
- **F — 事实证据** — 每个声明链接到具体证据
- **E — 到期意识** — 标记过时数据的风险（对标准至关重要）
- **R — 审核格式** — 使用表格分离事实与推论

**S-A-F-E-R 结构化输出模板：**
```
将你的答案以具有以下字段的表格返回：
  声明 | 证据 | 来源 | 来源日期 | 置信度 | 需要检查
```

**自我审核提示词：**
```
「列出你答案中 5 个最重要的事实声明。对每个声明，提供：1) 最佳来源，2) 日期，3) 用于验证的搜索查询。」
```

**为何有效：** 这将举证责任交还给人工智能。当系统必须明确标注内容出处时，幻觉往往不攻自破。

## 8. 什么有效——什么无效

| 有效性 | 提示词添加 |
|--------|-----------|
| **最有效** | 「仅使用这些来源」· 「如果不确定请说『我不知道』」· 「每个声明引用来源与日期」· 「标记无支持声明」· 「先提取确切引用，然后回答」 |
| **中等有效** | 「摘要你的假设」· 「列出可能弱点」· 「对每个声明给出置信度」 |
| **较不可靠** | 「解释你的思维链」· 「逐步思考」（单独）· 无来源核对的长推理 |

**关于思维链的说明：** 要求思维链 **不是** 防御幻觉的最佳方法。模型可以产生虚构逻辑——解释听起来令人信服但仍然错误。

更好替代方案：
- **简短推理** — 要求简短推理摘要
- **关键假设** — 询问做了哪些假设
- **什么错了？** — 询问「这可能哪里错了？」
- **每个声明的证据** — 要求每个声明的证据
- **验证什么？** — 询问「什么需要独立验证？」

## 9. 红旗 — 幻觉警告信号

| 旗标 | 警告信号 |
|------|----------|
| 🔴 **精确数字** | 无给定来源的具体数字 |
| 🔴 **找不到引用** | 无法在搜索引擎找到 |
| 🔴 **无名专家** | 「研究表明...」或「专家说...」但无姓名 |
| 🔴 **100% 自信语气** | 在微妙或有争议的主题上 |
| 🔴 **未知框架** | 「XYZ 七步模型」无人提及 |
| 🔴 **近期事件** | 过去 12–18 个月的任何内容可能过时 |
| 🟡 **看似合理但新颖** | 听起来正确但你从未听过 |
| 🟡 **略显奇怪的混合** | 正确信息与奇怪声明混合 |
| 🟡 **过时细节** | 工具、法律、软件版本或产品功能 |

## 10. 幻觉防御提示词模板

### 校准提示词
在任何研究或事实查找任务前使用：
```
指令（在你回答之前）：
- 告诉我你的置信度（高 / 中 / 低）
- 告诉我最不确定的是什么
- 标记任何时间敏感或司法管辖区特定的内容
- 告诉我哪些声明我应该验证以及在何处验证
- 告诉我是从一般训练还是从我提供的来源得出
```

### 香港法律 / 法规提示词
用于任何法律或法规问题：
```
任务：
我在香港情境中询问这个。

指令：
- 告诉我是基于香港法律还是海外原则
- 指明你引用的具体香港条例、法规或指引
- 标记香港法律与英国或美国法律显著不同之处
- 告诉我是否应该在 elegislation.gov.hk 验证或咨询香港律师
```

### 摘要检查提示词
用于要求人工智能摘要文件时：
```
任务：摘要这个文件。

指令（在你的摘要之后）：
- 列出原始文件中任何复杂、有条件或微妙的部分，并注意你的摘要是否保留了这种复杂性
- 识别不可省略的条件或例外
- 提示我应该复查的任何数字、门槛或日期
```

### 圣经 / 神学安全提示词
用于任何涉及圣经或神学内容的任务：
```
任务：我需要帮助 [涉及圣经或神学的任务]。

指令：
- 不要将神学诠释呈现为权威
- 如果不同基督教传统持有不同观点，请列出
- 标记任何你不确定的圣经引用
- 我将在使用前在圣经中验证所有圣经内容
```

## 11. 人工审核关口

在使用任何人工智能输出前，回答这四个问题：

| 问题 | 如果否 — 在此停止 |
|------|------------------|
| **阅读完整输出？** | 不要略读并假设 |
| **事实与引用已验证？** | 不要转发未验证声明 |
| **有合格的人把关吗？** | 不要依赖人工智能进行专业判断 |
| **能够支持它？** | 如果不能 — 检查更多 |

> [!important] 责任测试：  
> 如果受到质疑，我是否愿意支持这个输出？  
> 如果是 — 你已经做得足够。如果否 — 在使用前检查更多。

## 12. 按任务类型的幻觉风险

| 任务 | 风险 | 关键防御 |
|------|------|----------|
| **摘要你的文件** | 低–中 | 检查条件与例外是否保留 |
| **从你的笔记起草** | 低 | 使用前阅读完整输出 |
| **研究事实或法律** | 高 | 在主要来源验证 |
| **生成引用** | 非常高 | 绝不在确认来源存在前使用 |
| **香港法律** / 法规问答 | 非常高 | 在官方香港来源验证或咨询律师 |
| **繁体中文翻译** | 中 | 与合格双语审核员检查术语 |
| **圣经诠释** | 高 | 在圣经中验证；咨询你的牧师 |
| **资助统计数据** | 非常高 | 绝不让人工智能捏造统计数字；指示人工智能使用 [待填写] 等占位符代替 |

## 13. 如果幻觉已经发生

- **立即纠正** — 通知任何收到错误信息的人
- **保留记录** — 保留原始人工智能输出与你的纠正
- **评估影响** — 谁收到了它，可能影响了哪些决策
- **审查缺口** — 哪个检查本应发生但没有？
- **更新你的流程** — 添加本应捕捉这个的具体检查
- **《个人资料（私隐）条例》义务？** — 如果涉及个人信息，这可能触发报告义务；立即提出

## 14. 快速参考卡

```
在使用人工智能输出前：
- [ ] 我是否提供了来源文件给人工智能参考？ — 减少虚构
- [ ] 我是否要求不确定性标记？ — 揭示弱点
- [ ] 我是否要求来源？ — 验证它存在
- [ ] 我是否阅读了完整输出？ — 不仅仅是第一段
- [ ] 我愿意为这个背书吗？ — 责任测试

高风险 — 始终独立验证：
- 具体统计数据 · 具名案例或法律 · 日期与门槛
- 引用与参考文献 · 近期事件 · 香港法规结论

香港主要来源 — 收藏这些：
- pcpd.org.hk · elegislation.gov.hk · gov.hk
- cr.gov.hk · sfc.hk · hkma.gov.hk
```
