# 人工智能用例分类评分卡

> [!quote] 目的：  
> 在投入时间和资源于任何人工智能项目之前，花 20 分钟回答这些问题。  
> 评分告诉你是应该现在开始、先修复某些问题，还是完全停止。

**本评分卡用途：** 一个结构化工具，用于决定人工智能用例是否应该现在开始、作为小型试点开始、等待，或停止。

**本评分卡非：** 高分用例必然成功，或低分用例必然失败的保证。这是一个思考工具，而非认证。最终决定仍由相关人员和组织作出。

---

首先完成本节。如果你无法清晰回答所有字段，该用例尚未准备好进行评分。

| 字段 | 你的答案 |
|------|----------|
| **用例名称** | |
| **组织** | 中小企业 / 教会 / 非营利组织 / 其他： |
| **负责人 / 倡导者** | |
| **人工智能协助什么任务？** | |
| **谁将使用它？** | |
| **当前的痛点或问题** | |
| **当前的人手流程** | |
| **期望的改进** | 时间 / 质量 / 一致性 / 成本 / 其他： |
| **这能否是简单的工作流程而非人工智能？** | 是 / 否 / 不确定 |

---

### 如何评分

诚实回答每个问题。使用下方的评分指南。最后将每节总分相加。

| 分数 | 含义 |
|------|--------|
| **2** | 是，已清晰处理 — 无疑虑 |
| **1** | 部分处理或不确定 |
| **0** | 未处理、未知，或适用红旗 |

**最终分数解读：**

| 总分 | 决定 |
|------|------|
| 14–17 | ✅ **绿色：开始小型试点** — 条件良好 |
| 10–13 | ⚠️ **琥珀色：先修复** — 处理差距，然后重新评分 |
| 6–9 | 🔴 **危险：未准备好** — 重大差距；暂时不要开始 |
| 0–5 | ⛔ **红色：停止** — 根本性问题；人工智能现时不是正确路径 |

## 2. 3P：安全使用评估（0–6 分）

### P1 · 目的（0–2 分）
**这个人工智能用例的目的有多清晰？**

| 分数 | 情况 |
|------|------|
| **2** | 任务界限清晰：我们确切知道人工智能将做什么、谁审核输出，以及成功是什么样子 |
| **1** | 任务部分定义，但某些角色、界限或成功标准仍不清晰 |
| **0** | 目的模糊（「使用人工智能改善运营」），或人工智能被考虑是因为其他人正在使用它 |

**P1 红旗 — 如适用任何一项，评分 0：**
- [ ] **模糊任务** — 仅描述为「使用人工智能改善我们的工作」
- [ ] **未命名审核者** — 未指定人工审核者
- [ ] **成功不可衡量** — 无法用一句可衡量的句子描述成功
- [ ] **人员决策** — 任务涉及人员的资格、获取或福利

### P2 · 权限（0–2 分）
**我们对允许与人工智能一起使用的数据了解多少？**

| 分数 | 情况 |
|------|------|
| **2** | 我们已检查《个人资料（私隐）条例》合规性；数据已匿名化或明确允许；不涉及敏感个人信息 |
| **1** | 我们已考虑数据权限，但尚未正式检查《个人资料（私隐）条例》；可能涉及某些敏感信息 |
| **0** | 我们未考虑数据权限；或涉及敏感个人、牧养、人力资源或受规管数据 |

**P2 红旗 — 如适用任何一项，评分 0：**
- [ ] **未检查《个人资料（私隐）条例》** — 敏感个人信息将涉及而无《个人资料（私隐）条例》评估
- [ ] **工具未获批准** — 未检查数据条款
- [ ] **人员决策** — 任务涉及人员的资格、获取或福利

**香港关口 — 繁体中文可读性：**
- [ ] **繁体中文文件？** — 是否为打字数字格式（非扫描图像）？（未测试的扫描繁体中文，尤其是手写 = 自动红色。测试并解决问题前不要继续。）

> [!warning] 使用图像会引入原生文本没有的「隐藏」风险：  
> - **无声幻觉：** 人工智能工具可能在未告知用户的情况下「修复」混乱的手写或模糊的繁体中文字符，可能改变文件的含义。  
> - **验证负担：** 当来源是图像时，人工审核员必须更努力地将输出与图像来源交叉参考。

## 3. 3R：项目成功评估（0–6 分）

### R1 · 正确的问题（0–2 分）
**人工智能真的是这个问题的正确解决方案吗？**

| 分数 | 情况 |
|------|------|
| **2** | 人工智能解决真实、具体、重复出现的痛点；已考虑替代方案，人工智能对此任务明显更好 |
| **1** | 人工智能可能在此有用，但案例尚未测试；我们不确定更简单的工具是否可行 |
| **0** | 人工智能被提议而无清晰的问题分析；或真正问题是流程或人员问题，而非工具问题 |

**帮助评分 R1 的诊断问题：**
- **一句话？** — 这解决什么确切问题？
- **当前变通方法？** — 这个问题目前如何处理？什么会出错？
- **更简单的解决方案？** — 更好的电子表格、模板或标准作业程序能否在无人工智能的情况下解决这个问题？
- **涉及反对者？** — 组织中谁会反对这个，你是否已将他们纳入？

**R1 红旗 — 如适用任何一项，评分 0：**
- [ ] **模糊问题** — 「使用人工智能改善我们的工作」不是用例

### R2 · 就绪（0–2 分）
**我们是否准备好推进 — 跨越数据、组织、流程和治理？**

> [!note] 为何「就绪」涵盖的不仅是数据：  
> 大多数人工智能项目失败不是因为技术不好，而是因为其他方面未就绪：数据混乱、团队未为变革做好准备、现有流程无处容纳人工智能输出，或无人思考谁负责。这个问题在承诺之前检查所有四个就绪维度。

| 分数 | 情况 |
|------|------|
| **2** | 所有四个维度已处理：数据已整理且允许；人员已为变革做好准备；流程已设计以接收人工智能输出；问责和治理已到位 |
| **1** | 大多数维度已处理，但一两个有差距需要在试点期间注意 |
| **0** | 一个或多个维度有重大差距 — 数据不可用、人员未准备、流程未定义，或治理缺失 |

**R2 红旗 — 如适用任何一项，评分 0：**
- [ ] **数据不可用** — 来源文件混乱、过时、不完整，或无法机器读取
- [ ] **未命名负责人** — 此项目无负责人或赞助者

#### R2a — 数据就绪

| 检查 | 状态 |
|------|------|
| **原生数字文本** — 可搜索，不仅是文本图片 | 通过 / 失败 |
| **繁体中文图像可靠性** — 如为扫描/手写，已测试准确性 | 通过 / 失败 |
| **格式一致** — 来源间的命名和结构 | 通过 / 失败 |
| **《个人资料（私隐）条例》通过** — 无敏感个人信息；原则 3 检查已完成 | 通过 / 失败 |
| **足够完整** — 对于预期任务 | 通过 / 失败 |
| **有权使用** — 此数据用于人工智能处理 | 通过 / 失败 |

*如 2 行或以上失败：数据未就绪。仅此一项可能评分 R2 = 0。*

#### R2b — 组织就绪

| 检查 | 状态 |
|------|------|
| **领导层批准** — 正式批准此用例 | 通过 / 失败 |
| **命名问责人** — 负责人负责人工智能工作流程和输出 | 通过 / 失败 |
| **最终用户已准备** — 职员参与并准备好变革 | 通过 / 失败 |
| **反对者已纳入** — 已识别并纳入，而非绕过 | 通过 / 失败 |
| **培训已计划** — 为最终用户提供导向 | 通过 / 失败 |

*组织就绪经常是真正的瓶颈。技术很少是。*

#### R2c — 流程就绪

| 检查 | 状态 |
|------|------|
| **工作流程已映射** — 我们知道人工智能输出将落在何处 | 通过 / 失败 |
| **流程已重新设计** — 包括人工智能作为起草步骤，并有人工审核 | 通过 / 失败 |
| **错误路径已定义** — 我们知道当人工智能产生错误时会发生什么 | 通过 / 失败 |
| **角色已分配** — 起草者、审核者和批准者已命名 | 通过 / 失败 |

#### R2d — 治理就绪

| 检查 | 状态 |
|------|------|
| **政策已到位** — 人工智能使用政策存在或正在采用，于上线前 | 通过 / 失败 |
| **升级路径** — 如人工智能产生有害或错误内容，有清晰路径 | 通过 / 失败 |
| **质量标准** — 负责人能够判断什么样的输出是好的 | 通过 / 失败 |
| **审核计划** — 试点后审核和改进工作流程的计划 | 通过 / 失败 |

### R3 · 现实的期望（0–2 分）
**时间、成本、精力和预期结果是否已诚实评估？**

| 分数 | 情况 |
|------|------|
| **2** | 清晰、可衡量的成功标准已定义；时间和资源估计有根据；我们接受人工智能输出需要审核 |
| **1** | 粗略的成功标准但无坚实的资源估计；预期审核负担但未建模 |
| **0** | 成功模糊；或预期人工智能在无人工审核的情况下工作；或承诺变革性结果而无证据 |

**R3 = 0 的警告信号：**
- **「节省 50% 时间」** — 无基线证据
- **「只需插入即可」** — 假设它在无流程设计的情况下工作
- **「供应商说简单」** — 无独立验证
- **工具安装完成** = 成功 — 不衡量实际成果
- **无基线** — 无当前指标可比较改进

**R3 红旗 — 如适用任何一项，评分 0：**
- [ ] **无基线（定量案例）** — 无当前指标可比较时间、成本或绩效改进
- [ ] **未定义价值（定性案例）** — 无清晰方式判断输出是否更好（例如清晰度、一致性、风险）
- [ ] **未命名负责人** — 此项目无负责人或赞助者
- [ ] **完全自动化** — 未计划人工审核

## 4. 实际适配度评估（0–5 分）

**注意：** 第 4 节最高 5 分，总可能分数为 17 分。

### F1 · 风险等级（0–2 分）
**如果人工智能在此用例中产生错误，会有多严重？**

| 分数 | 情况 |
|------|------|
| **2** | 低风险：错误容易捕捉和纠正；无外部方受影响；无敏感内容 |
| **1** | 中风险：错误可能令组织尴尬或需要纠正努力；某些外部可见性 |
| **0** | 高风险：错误可能伤害人员、造成法律风险、损害牧养关系，或违反规例 |

**F1 红旗 — 如适用任何一项，评分 0：**
- [ ] **牧养内容** — 用例涉及牧养辅导或灵性指导
- [ ] **资格决策** — 用例涉及受益人资格
- [ ] **大规模个人信息** — 大规模敏感个人信息
- [ ] **无审核关口** — 输出在无人工审核的情况下到达外部
- [ ] **专业资格** — 任务需要法律、医疗或财务专业知识

## 5. 建议的起始模式

## 7. 试点设计（如决定推进，请填写本节）

与决定日志一起完成本节。保留副本与项目记录一起存档。

设计良好的试点必须涵盖以下各项：

- [ ] **范围** — 一个具体、有界限的任务（非「我们所有的通讯」）
- [ ] **持续时间** — 最多 2–4 周
- [ ] **容量** — 扩展前 5–10 个真实输出
- [ ] **指定审核者** — 在使用前阅读每个人工智能输出
- [ ] **审核点** — 在推进前需要人工审核的指定检查点
- [ ] **成功指标** — 开始前定义
- [ ] **停止条件** — 什么会使我们停止试点？
- [ ] **签署人** — 谁在更广泛推广前批准？
- [ ] **退出条件** — 例如「如错误率 > 20%，我们停止」
- [ ] **记录保存** — 人工智能产生什么及什么被更改的日志

## 8. 避免从这些开始的用例

特别是对于教会和非营利组织 — 不要从这些开始：

- **牧养人工智能** — 通过人工智能进行辅导、祈祷事工或灵性指导
- **神学机器人** — 呈现为权威的问答机器人
- **自动化成员回应** — 未经逐条人工审核
- **人员决策** — 护理转介、财务协助、志愿者适合性，或职员事项
- **成员个人信息** — 输入任何公共人工智能工具
- **牧养记录** — 机密文件在任何人工智能工具中

## 9. 香港特定提醒

- [ ] **繁体中文可读性已测试** — 在任何人工智能处理之前
- [ ] **《个人资料（私隐）条例》原则 3 已评估** — 对于任何个人信息
- [ ] **资助者人工智能政策已检查** — 如用例涉及资助申请
- [ ] **香港规例已验证** — 在官方来源，而非从人工智能输出假设
- [ ] **牧养范围已确认** — 神学内容已明确排除

## 10. 最佳早期用例（参考）

这些持续高分且是低风险起点：

| 用例 | 为何运作良好 |
|------|-------------|
| **通讯起草** | 文字密集型、重复性、人手在发送前审核 |
| **会议回顾** | 清晰来源（会议）、结构化输出、人手验证 |
| **文件摘要** | 来源就在那里 — 无法幻觉文件中没有的内容 |
| **政策 / 标准作业程序问答** | 有界限来源、已知问题、清晰人手后备 |
