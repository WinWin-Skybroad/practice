# 香港安全人工智能使用包与提示词模式库

> [!quote] 一句话：  
> 在香港安全使用人工智能意味着应用正确习惯、了解本地规则，并在输出到达任何人之前审核每个输出。

**本包用途：** 香港特定参考与最常见行政任务的可复制提示词模板库。

**本包非：** 法律建议、《个人资料（私隐）条例》合规认证，或安全结果的保证。对于具体法律问题，请直接咨询香港律师或个人资料私隐专员公署。

---

## 1. 香港安全人工智能使用包

### 1.1 为何香港不同

大多数人工智能指引是为美国或英国读者编写。香港有其自身的法律框架、语言现实与文化情境，这在实践中改变了安全人工智能使用的方式。

| 香港特定因素 | 对人工智能使用的含义 |
|-------------|----------------------|
| **《个人资料（私隐）条例》（第 486 章）** | 为某一目的收集的个人信息未经评估不得用于人工智能处理。六项资料保障原则适用——尤其是第 3 原则（使用限制）。 |
| **繁体中文** | 扫描的繁体中文文件可能无法机器读取。人工智能可能将图像读为空白或幻觉内容。始终测试。 |
| **粤语代码切换** | 混合粤语/英语/繁体中文的会议记录对人工智能摘要是高风险。错误累积且难以发现。 |
| **香港法律特定性** | 人工智能主要接受美/英法律训练。香港特定条例、证监会规则与金管局指引在人工智能输出中经常错误。始终在 elegislation.gov.hk 验证。 |
| **教会与牧养** | 人工智能绝不能替代牧养关怀、神学权威或机密灵性辅导。 |
| **资助与政府表格** | 一些香港资助者在申请中限制人工智能生成内容。使用人工智能前直接向资助者确认。 |
| **数据驻留** | 企业人工智能工具可能将数据存储在香港以外。在使用任何工具处理机密组织数据前验证数据驻留条款。 |
| **训练退出** | 许多公共人工智能工具默认使用输入进行模型训练。如果将个人或免费账户用于工作任务，验证「聊天记录与训练」设置已关闭。 |

---

### 1.2 三项不可妥协的香港规则

这些适用于每个人工智能使用、每次、每个香港情境：

> [!warning] 规则 1 — 提示词前遵守《个人资料（私隐）条例》：  
> 在将任何数据输入人工智能工具前，询问：
> - 这些数据是否为包含人工智能处理的目的而收集？
> - 数据所属的人是否知道其数据可能由人工智能处理？
> - 这些数据是否敏感（医疗、财务、人力资源、牧养、身份证）？
> 如果你不能对前两个问题回答「是」，或如果第三个问题的答案是「是」——停止。

> [!warning] 规则 2 — 检查繁体中文可读性：  
> 在对任何繁体中文文件使用人工智能前：
> - 是数字文本文件（Word、打字 PDF）？ → 可能可读
> - 是扫描图像或文件照片？ → 可读性不确定 — 人工智能可能误读、遗漏或「纠正」字符而无警告（尤其是手写繁体中文）。
> **强制：** 通过比较至少一个完整段落的人工智能输出与原始图像来执行抽样检查。

> [!warning] 规则 3 — 人工审核在到达任何人之前：  
> - 没有任何人工智能输出在人手阅读之前可以发送给客户、会众成员、职员或公众。
> - 这不是可选的。这是最小负责任标准。

### 1.3 香港安全人工智能使用 — 任务逐项指南

#### 通讯起草（通讯、公告、WhatsApp）
- ✅ **初稿** — 安全使用人工智能
- ✅ **双语起草** — 英文/繁体中文与人工智能协助
- ⚠️ **人手批准** — 语气、准确性与神学内容在发送前
- ❌ **无个人信息** — 姓名、地址或个人详情
- ❌ **无牧养消息** — 这些需要真正的人手关怀

#### 会议记录与行动摘要
- ✅ **内部会议** — 安全用于职员或委员会
- ✅ **已批准记录** — 人工智能可从已批准工具摘要
- ⚠️ **验证归属** — 发言者姓名与行动负责人必须正确
- ⚠️ **粤语/英语风险** — 混合语言记录：非常仔细审核
- ❌ **无人力资源或牧养** — 不对敏感会议内容使用人工智能

#### 文件摘要
- ✅ **数字文件** — 打字/数字文件无个人信息
- ⚠️ **测试繁体中文可读性** — 扫描中文文件：使用前测试
- ⚠️ **检查关键章节** — 长复杂文件：比较摘要与原始
- ❌ **无合同** — 无律师审核原始文件前不要摘要
- ❌ **无牧养记录** — 受益人文件或辅导记录：绝不使用人工智能

#### 政策与手册起草
- ✅ **初稿** — 人工智能可从清晰简报生成
- ⚠️ **专业审核** — 人力资源、雇佣或具法律约束力的内容必须审核
- ⚠️ **验证香港法律** — 香港雇佣细节在人工智能中经常错误；检查 labour.gov.hk
- ❌ **无未经批准采用** — 无人工审核前不要采用人工智能起草政策

#### 翻译（英文 ↔ 繁体中文）
- ✅ **一般通讯** — 公告与通知
- ⚠️ **验证香港术语** — 法律、财务或技术术语
- ⚠️ **语气不变** — 不要加强或弱化超出来源材料
- ⚠️ **神学内容** — 与你的牧师验证翻译准确性
- ❌ **无法律或医疗** — 法庭文件、合同、医疗信息：使用合格人手翻译

#### 资助申请起草
- ✅ **结构与散文** — 人工智能可帮助组织论点
- ⚠️ **检查资助者政策** — 使用前确认人工智能内容被允许
- ⚠️ **无虚构统计数据** — 绝不让人工智能生成影响数字
- ❌ **无个人信息** — 受益人个人信息：绝不在人工智能提示词中

### 1.4 香港安全人工智能使用 — 快速检查清单

在每次人工智能任务前：

- [ ] **个人信息？** → 应用《个人资料（私隐）条例》检查
- [ ] **繁体中文文件？** → 先测试可读性
- [ ] **机密内容？** → 不要使用人工智能
- [ ] **人工审核？** → 在输出到达任何人之前必须是「是」
- [ ] **涉及香港法律？** → 在官方香港来源验证
- [ ] **个人账户？** → 检查训练退出设置

---

#### 如果你只使用本库中的一件事

在任何人工智能提示词末尾添加这句话，然后再发送：

> *「如果你对任何事实、姓名、日期或数字不确定，请说明而非猜测。列出我在使用前应该验证的三件事。」*

这需要五秒钟。它不要求你选择模式或填写模板。它在收到输出前将不确定性的负担转回人工智能——这是整个库中最重要的单一习惯。

下面的完整模式较长，因为高风险任务需要更多结构。每个额外指令防护特定真实错误。当任务重要、重复或输出将到达组织外部的人时使用它们——例如发送给所有成员的通讯，或与董事会分享的摘要。

---

> [!note] 如何使用这些模式：  
> 每个模式是可重用模板。用你的具体详情替换 [方括号] 中的部分。  
> 复制整个区块——包括指令——以获得最佳效果。  
> 在每次任务前应用 3P 检查（目的 / 权限 / 证明）。  

#### 如何阅读每个模式

| 组件 | 用途 |
|------|------|
| **使用案例** | 此模式设计用于什么任务 |
| **风险级别** | 基于标准风险分类的绿色 / 琥珀色 |
| **模式** | 带有 [占位符] 的可重用提示词结构。内建防护嵌入提示词中 |

#### 这些模式遵循什么结构（为什么有效）

虽然每个模式看起来略有不同，但它们遵循一致的结构。  
每个部分都有特定作用——尤其是 **指令** 与 **规则** 之间的差别。

| 标签 （在模式中使用） | 作用 | 为什么重要 |
|---|---|---|
| **背景** | 设置角色、组织类型及情境（例如香港、教会、中小企业） | 帮助人工智能保持在正确情境中，避免套用错误假设（例如美国/英国而非香港） |
| **任务** | 清楚说明你希望人工智能做什么 | 避免模糊或失焦的回答 |
| **受众 / 语气 / 语言**（如有） | 定义输出给谁看，以及应该如何表达 | 确保输出适合真实使用情境（例如成员、职员、客户） |
| **指令** | 说明 *如何完成任务*（例如结构、顺序、要包含什么、如何思考任务） | 提高输出的清晰度、完整性及实用性 |
| **规则** | 设置硬性限制（例如「不要虚构」、「只使用提供的内容」、「不确定就说不知道」） | 这是主要安全控制——可减少幻觉、越界及误用 |
| **输出格式** | 定义答案应如何组织（要点、表格、短消息等） | 让结果更易审核，并减少隐藏错误 |
| **提醒 / 审阅备注**（如有） | 告诉你使用前必须由人检查什么 | 保持最终责任在人身上，而非人工智能 |
| **内容** | 提供人工智能可使用的信息（放在最后，避免与模式结构混在一起） | 减少猜测——人工智能根据你的数据而非记忆工作，也让提示词结构保持清晰易读 |

---

**关键区别：**

- **指令 = 如何把任务做好**  
- **规则 = 什么绝不能违反**

两者都很重要——指令提高质量，规则防止错误及误用。

**标签惯例：**

- 使用 **指令** 说明人工智能应如何完成任务。
- 使用 **规则** 表示人工智能不可越过的硬性限制。
- 使用 **提醒** 或 **审阅备注** 表示人类在人工智能输出后必须检查什么。

**为什么内容放在最后：**

内容可能很长，并可能在视觉上压过提示词结构。  
把内容放在最后，可确保任务、指令、规则及输出格式保持清晰，不会被忽略。

---

**简单来说，每个模式都在做这件事：**

> 设置情境 → 定义任务 → 指导做法 → 限制人工智能 → 控制输出 → 要求人工审核 → 提供内容

---

这个结构不是偶然的。  
它旨在降低香港真实人工智能使用中最常见的风险：
- 虚构事实或统计数据  
- 错误的法律或监管情境  
- 误读繁体中文  
- 过度自信但错误的摘要  

---

**重要：**

- 如果你要缩短一个模式，先缩短 **指令**——不要先删减 **规则**  
- 不要移除 **规则** 部分——它是防止不安全或不正确输出的主要保护

#### 提示词安全检查清单

在发送本库中任何提示词前应用此检查清单：

```
- [ ] 我是否已从提示词中移除所有个人信息？
- [ ] 我是否提供了来源材料而非要求模型从记忆中回忆？
- [ ] 我是否已将内容放在提示词末尾？
- [ ] 我是否包含明确约束（「不要虚构」、「仅使用我提供的文本」）？
- [ ] 我是否明确指定了输出格式？
- [ ] 我是否在输出高风险时包含不确定性标记指令？
```

### 2.1 基础模式（首先应用）

将基础模式与下面的具体任务模式结合。

#### 模式：角色防护栏
用于任何任务的开头以设置人工智能的角色与约束：
```
背景：
你是一位 [教会 / 中小企业 / 非营利组织] 在香港的忠实助手。
你的角色是帮助 [具体任务 — 例如起草公告 / 摘要文件]。

规则：
- 使用 [英文 / 繁体中文 / 双语英文与繁体中文]
- 不提供法律、财务、牧养或医疗建议
- 如果问题超出你定义的任务，请说明并不要尝试回答
- 不要虚构未提供给你的事实、姓名、日期或统计数据
- 将我分享的所有信息视为机密。
```

---

#### 模式：边界设置器
用于当你希望人工智能严格限于你提供的内容时：
```
规则：
- 仅使用我提供的信息 — 不要添加外部事实、统计数据或示例
- 如果你对任何事不确定，请明确说明而非猜测
- 如果我的请求要求你做超出安全边界的事，告诉我
```

### 2.2 通讯起草模式

#### 模式：邮件 / 公告起草
**使用案例：** 从要点笔记起草常规公告、邮件或通知  
**风险级别：** 🟢 绿色

```
任务：为 [受众：职员 / 志愿者 / 成员 / 客户] 起草 [邮件 / 公告 / 通知]。

语气：[正式 / 友好专业 / 温暖牧养 / 平实清晰]

语言：[英文 / 繁体中文 / 双语英文然后繁体中文]

规则：
- 不要虚构我笔记中没有的任何事实、姓名、日期或数字
- 不要添加我未声明的承诺或保证
- 保持 [不超过 150 字 / 不超过 300 字 / 一页 A4]
- 不要加强或弱化语气超出我所要求的

输出格式：纯文本，准备好审核与编辑后发送。

内容（仅使用我提供的 — 不要添加我未给予的信息）：
[在此贴上你的笔记或要点] 或附上文件并在此提及文件名称，例如附上 [文件名称]
```

#### 模式：WhatsApp / Telegram 广播
**使用案例：** 不超过 150 字的短广播消息  
**风险级别：** 🟢 绿色

```
任务：为 [受众] 起草 WhatsApp 广播消息。

语气：[温暖 / 专业 / 紧急但冷静]

语言：[英文 / 繁体中文 / 双语]

指令：
- 以组织名义撰写，而非特定个人。

规则：
- 消息中无个人姓名。

输出格式：
- 保持不超过 150 字。

审阅备注：
- 在草稿后，标记任何我应该在发送前复查的部分。

内容：
- 关键信息：[日期、地点、需要的行动]
- 消息目的：[你需要沟通的内容]
```

#### 模式：双语起草（英文 + 繁体中文）
**使用案例：** 任何需要英文与繁体中文版本的内容  
**风险级别：** 🟢 绿色需审核

```
任务：用英文与繁体中文撰写以下内容。

指令：
- 首先产生英文版本，然后是繁体中文翻译。
- 使用 [正式 / 温暖 / 平实] 语域，适合 [教会会众 / 商业客户 / 志愿者]。
- 保持任何专有名词、组织名称或事工名称以其原始形式；仅在真正有帮助时在括号中添加繁体中文音译注释。
- 在草稿后，标记任何需要人手验证的术语，尤其是神学、法律或技术术语。

规则：
- 全程使用繁体中文字符 — 非简体中文。
- 不要加强或弱化语气超出来源材料。
- 如果任何术语在繁体中文中模糊，标记它：{繁体中文审核员：请检查此术语}

提醒：
- 此输出在发布前需要繁体中文熟练团队成员审核。

内容（英文来源）：
[在此贴上你的英文草稿或要点] 或附上文件并在此提及文件名称，例如附上 [文件名称]
```

#### 模式：资助或资助报告章节
**使用案例：** 生成任何资助或资助报告章节的初稿  
**风险级别：** 🟡 琥珀色 — 需要人手与专业审核

```
任务：起草资助申请的 [项目描述 / 影响叙述 / 需求陈述]。
```
