# RAG 知識庫就緒度評估

**在構建從您的文件回答的人工智能之前**

> [!quote] 用途：  
> RAG（檢索增強生成）讓人工智能通過搜尋您自己的文件來回答問題，而非僅依賴其訓練數據。這聽起來很強大——確實可以如此。但僅當您的文件已整理、最新、有組織且法律上允許使用時，它才有效。  
> 本評估幫助您在開始構建之前確認您是否已準備就緒。

**本評估用途：** 針對任何依賴從文件庫搜尋和檢索的人工智能使用場景的結構化就緒度檢查。

**本評估非：** 技術 RAG 實施指南或保證通過評分即代表您的系統將正確運作。文件就緒度可降低幻覺風險——但不消除它。

---

## 1. 什麼是 RAG 以及為何就緒度重要？

在標準人工智能對話中，模型依賴其訓練數據。在 RAG 系統中，模型首先從您提供的文件庫檢索相關內容，然後使用該內容生成答案。

這意味著：**您答案的質素受限於您文件的質素。**

建立在壞文件上的 RAG 系統會產生壞答案——且充滿自信。與簡單搜尋不同，RAG 不向您顯示原始文件。它綜合它們。錯誤在出問題前是不可見的。

**常見 RAG 失敗模式：**
- **過時政策** — 用去年的規則回答客戶
- **空白繁體中文文件** — 掃描的中文返回空白；人工智能捏造答案
- **格式缺口** — 混合文件格式可能導致檢索缺口，使部分內容無法被人工智能找到
- **個人資料洩露** — 敏感資料最終嵌入人工智能回應
- **矛盾答案** —  矛盾文件產生矛盾答案
- **缺失來源** — 當正確來源缺失於文件庫時，人工智能仍自信回答

---

## 2. 評估結構

本評估有四個關口。任何關口的失敗意味著在構建 RAG 系統之前必須修復該關口的工作。

| 關口 | 檢查內容 | 失敗影響 |
|------|----------|----------|
| **關口 1 — 法律許可** | 您是否允許在人工智能系統中使用這些文件？ | 數據洩露、違反《個人資料（私隱）條例》、信任損害 |
| **關口 2 — 文件質素** | 文件是否機器可讀、最新、準確且一致？ | 幻覺、缺口、錯誤答案 |
| **關口 3 — 知識架構** | 文件庫是否組織良好以便人工智能檢索正確內容？ | 檢索失敗、無關答案 |
| **關口 4 — 管治** | 是否有控制措施使系統隨時間保持準確和有界限？ | 漂移、不受控範圍、未檢測錯誤 |

> [!warning] 若任何關口未能通過，必須先解決該關口的問題，然後才可繼續構建。切勿在關口問題尚未解決的情況下，試點任何 RAG 系統。

---

## 3. 就緒度關口 — 四個順序檢查

按順序完成每個關口。任何關口的失敗都是停止條件 — 在進入下一個關口之前解決它。如果關口 1 有尚未解決的項目，不要進入關口 2。關口這樣設計是有意的：構建後發現法律或數據許可問題比現在發現成本高得多。

### G1 關口 1 — 法律許可

回答每個問題。此關口中任何單一的「否」或「不確定」意味著： **停止並在繼續前解決。**

#### G1.1 數據收集目的
- [ ] **兼容目的** — 文件創建目的與人工智能處理兼容
- [ ] **目的闡述** — 我們能解釋為何人工智能處理與原始收集目的一致

> [!warning] 《個人資料（私隱）條例》原則 3：  
> 為某一目的收集的個人資料不得在未經同意的情況下用於實質上不同的目的。使用人力資源檔案、客戶記錄或牧養筆記為人工智能問答系統提供動力幾乎肯定是需要新鮮評估的新目的。

#### G1.2 個人資料評估
- [ ] **已識別個人資料** — 已識別包含姓名、身份證、聯絡方式、健康、財務或人力資源資訊的文件
- [ ] **已排除或正當化** — 個人資料已排除於文件庫之外，或包含已確認法律上許可並記錄
- [ ] **已排除牧養記錄** — 文件庫中無受益人記錄、輔導筆記、祈禱事項或敏感披露

#### G1.3 存取控制
- [ ] **用戶僅見許可內容** — RAG 系統僅展示查詢用戶許可的文件
- [ ] **無跨角色洩露** — 無員工檢索不同團隊或角色文件的風險
- [ ] **受保護敏感文件** — 人力資源、財務和牧養文件已排除或位於存取控制之後

#### G1.4 工具和供應商條款
- [ ] **已審閱供應商條款** — 已審閱人工智能工具供應商的服務條款和數據處理政策
- [ ] **理解訓練條款** — 工具是否保留、索引或訓練上傳的文件
- [ ] **可接受的數據駐留** — 工具的數據駐留條款對此內容類型可接受

#### G1.5 第三方內容權利
- [ ] **已確認擁有權** — 我們擁有或有權利使用所有文件進行人工智能處理
- [ ] **已排除版權內容** — 無第三方版權內容未經檢查許可條款
- [ ] **允許政府文件** — 在其許可條款內使用

#### G1.6 保密性和敏感性
- [ ] **已排除機密** — 無標註為機密或受限的文件除非另行批准
- [ ] **已排除商業秘密** — 無商業敏感資訊或定價數據
- [ ] **已排除法律特權** — 已排除法律特權通訊

#### 關口 1 結果：通過 / 失敗

> [!warning] 關口 1 是硬性停止：  
> 如果任何項目以上是「否」或「不確定」— 在解決前不要進入關口 2。  
> 構建後發現法律或數據許可問題比現在發現成本高得多。

### G2 關口 2 — 文件質素

#### G2.1 機器可讀性

| 文件類型 | 可讀性 | 行動 |
|------|----------|----------|
| 打字 Word / Google Docs | ✅ 通常可讀 | 驗證字符編碼 |
| 打字 PDF（數字文本） | ✅ 通常可讀 | 抽查文本提取 |
| 掃描 PDF — 英文 | ⚠️ 取決於光學字符識別 (OCR) 質素 | 測試提取；如需則應用 OCR |
| 掃描 PDF — 繁體中文 | 🔴 通常不可讀 | 必須先轉換為數字文本 |
| 圖像文件（文件的 JPG、PNG） | 🔴 作為文本不可讀 | 必須 OCR 並驗證 |
| WhatsApp / 訊息匯出 | ⚠️ 混合質素 | 納入文件庫前先整理和重新格式化 |
| 音頻/視頻轉錄 | ⚠️ 取決於轉錄質素 | 納入文件庫前先驗證準確性 |

- [ ] **僅數字文本** — 所有文件為機器可讀文本格式；無掃描圖像
- [ ] **按需轉換** — 表格、多欄佈局和格式化文件提取為純文本
- [ ] **已測試每個文件** — 提取代表性部分並驗證為準確
- [ ] **已測試繁體中文可讀性** — 已測試每個繁體中文文件的文本可選擇性
- [ ] **已轉換掃描繁體中文** — 所有掃描繁體中文文件轉換為機器可讀文本並驗證
- [ ] **已移除不可提取** — 已移除無法可靠提取的文件

**香港特定測試：** 對於任何繁體中文文件 — 嘗試選擇和複製一個段落。如果它複製為可讀字符，它可能是機器可讀的。如果它選擇為單個圖像塊，使用前需要 OCR 預處理。

#### G2.2 及時性和準確性
- [ ] **每個文件有版本日期** — 或最後審閱日期
- [ ] **已審閱舊文件** — 已檢查超過 [設定門檻] 的文件準確性
- [ ] **已移除過時內容** — 已更新或移除取代的政策、舊員工或過時程序
- [ ] **存在更新流程** — 政策變更時更新文件庫的流程
- [ ] **每個文件有命名負責人** — 負責更新
- [ ] **已抽查樣本** — 已檢查 3–5 個文件：每個文件 3–5 個具體事實已針對當前真實來源驗證
- [ ] **事實匹配現實** — 姓名、日期、費用、政策和程序匹配當前現實狀態
- [ ] **無衝突版本** — 或如果存在，已明確識別正確版本
- [ ] **已檢查 OCR 錯誤** — 已檢查掃描或 OCR 處理文件的提取錯誤

> [!warning] 陳舊文件是無聲幻覺來源：  
> RAG 系統不知道文件過時。它會自信地用去年的政策回答。在構建之前為每個文件添加日期標記並設定審閱週期。

#### G2.3 完整性
- [ ] **已映射問題** — 前 20 個常見問題已映射到具體文件：完全覆蓋 / 部分覆蓋 / 未覆蓋
- [ ] **存在關鍵政策** — 不僅部分覆蓋
- [ ] **已記錄例外** — 邊緣情況和升級路徑已記錄，不僅標準流程
- [ ] **缺口門檻** — 如果超過 25% 的目標問題未覆蓋，文件庫有導致人工智能猜測的缺口

#### G2.4 來源
- [ ] **已知來源** — 每個文件有已知來源；非「從某處下載」
- [ ] **命名負責人** — 每個文件有命名負責人
- [ ] **已追蹤轉換** — 掃描、OCR 或重新格式化的文件仍可追蹤回原始文件

#### G2.5 一致性和衝突
- [ ] **文件間一致** — 多個文件中相同主題覆蓋一致
- [ ] **已解決矛盾** — 已調和矛盾文件或指定一個版本為權威

> [!note] 真理層級：  
> 如果兩個文件對同一問題給出不同答案，提前建立哪一個是權威來源。無此，人工智能將產生矛盾答案取決於檢索哪個區塊。

#### G2.6 範圍和完整性
- [ ] **覆蓋真實問題** — 文件庫覆蓋用戶實際會問的問題

> [!note] 實用測試：  
> 取 10–20 個人工智能系統需要回答的真實問題。答案能否在您匯編的文件中找到？如果超過 3/10 無法從您的文件回答 — 文件庫對此使用場景不完整。

- [ ] **無幻覺缺口** — 無明顯缺口導致人工智能無內容檢索並可能幻覺
- [ ] **範圍有界限** — 已決定系統將回答什麼和不回答什麼
- [ ] **範圍外後備** — 範圍外問題有定義的後備回應

#### 關口 2 結果：通過 / 失敗

> [!warning] 關口 2 關鍵洞察：  
> 大多數組織在關口 2 發現其文件問題 — 而非技術設置。  
> 構建前整理文件，遠比上線後修正錯誤輸出更省時。

### G3 關口 3 — 知識架構

#### G3.1 相關性和範圍
- [ ] **使用場景聚焦** — 文件庫僅包含和使用場景有直接聯繫的文件；非共享儲存空間中的所有內容
- [ ] **已排除噪音** — 已移除無關或邊緣文件
- [ ] **書面範圍** — 包含什麼和不包含什麼，書面定義

**相關性測試：** 取 10–20 個人工智能系統需要回答的真實問題。答案能否在您匯編的文件中找到？如果超過 3/10 無法回答 — 文件庫對此使用場景不完整。

#### G3.2 結構和可檢索性
- [ ] **邏輯分類** — 按主題、部門或文件類型
- [ ] **標題和結構** — 有意義的標題；非一個長未劃分文本塊
- [ ] **有用的元數據** — 每個文件有標題、負責人、日期、主題、文件類型
- [ ] **可過濾** — 系統可按日期、部門或文件類型過濾
- [ ] **已拆分長文件** — 在邏輯邊界拆分以便檢索浮現正確部分
- [ ] **存在主索引** — 文件庫內容列表或索引
- [ ] **已移除重複** — 已合併重複或近似重複版本

#### G3.3 區塊設計和檢索測試
- [ ] **完整思想** — 區塊大小包含完整思想；非切割中途句子或中途政策
- [ ] **每個區塊來源元數據** — 文件名稱、部分、日期和版本
- [ ] **尊重繁體中文邊界** — 對於繁體中文內容，區塊尊重繁體中文句子和段落邊界
- [ ] **已測試代表性問題** — 已編寫和測試 10–20 個代表性用戶問題
- [ ] **浮現正確文件** — 檢索系統為代表性問題浮現正確文件
- [ ] **已測試範圍外** — 已測試至少 5 個範圍外問題；系統適當拒絕

#### G3.4 檢索質素測試
- [ ] **答案正確** — 已檢查測試答案：答案是否正確？是否引用正確來源？
- [ ] **檢索正確來源** — 正在檢索相關來源，非無關文件
- [ ] **已測試「我不知道」** — 系統在不知道時如此說；不幻覺
- [ ] **已識別壞結果類型** — 已識別和理解返回壞結果的查詢類型

#### G3.5 存取控制（《個人資料（私隱）條例》對齊）
- [ ] **尊重權限** — 檢索尊重用戶權限；用戶僅見許可文件
- [ ] **已排除或編輯敏感** — 索引前
- [ ] **審計追蹤** — 已記錄查詢和檢索區塊用於《個人資料（私隱）條例》問責

#### G3.6 語言和雙語處理
- [ ] **已決定語言** — 系統是否用英文、繁體中文或兩者回應
- [ ] **文件庫語言匹配** — 預期查詢語言
- [ ] **雙語一致性** — 對於雙語系統：兩種語言表達相同政策一致

#### 關口 3 結果：通過 / 失敗

### G4 關口 4 — 管治

#### G4.1 輸出驗證
- [ ] **已引用來源** — 系統為每個聲明引用來源；用戶可檢查來源部分
- [ ] **已標記不確定性** — 當系統不確定時，它如此說而非猜測
- [ ] **反饋流程** — 用戶標記他們認為錯誤答案的清晰流程

#### G4.2 人工審核
- [ ] **命名審核者** — 負責在高風險使用前審核人工智能回應的人
- [ ] **外部使用前審核** — 任何 RAG 輸出用於外部通訊或正式決策前需要人工審核
- [ ] **已披露人工智能** — 用戶知道他們與人工智能互動，非人類

#### G4.3 持續維護
- [ ] **命名文件庫負責人** — 負責保持文件最新
- [ ] **已定義審閱節奏** — 文件將多久檢查和更新一次？
- [ ] **更新流程** — 政策變更時，更新相關文件的清晰流程
- [ ] **已歸檔過時** — 已歸檔或移除過時文件；非留在上線文件庫
- [ ] **變更日誌** — 任何給定時間上線的文件庫版本的版本記錄

#### G4.4 範圍邊界
- [ ] **範圍聲明** — 系統有清晰定義範圍：它將回答什麼和不回答什麼
- [ ] **優雅拒絕** — 範圍外問題產生拒絕和轉介到人類
- [ ] **始終範圍外** — 系統不嘗試回答：牧養關懷、醫療、法律、受益人資格或人力資源決策
- [ ] **已告知用戶** — 已告知用戶系統能做什麼和不能做什麼

#### G4.5 監控和錯誤回應
- [ ] **用戶標記** — 用戶報告錯誤答案的機制
- [ ] **調查流程** — 調查報告錯誤的定義流程
- [ ] **暫停規則** — 在什麼條件下系統將離線審閱？
- [ ] **事件後學習** — 已記錄並反饋到文件改進
- [ ] **問題記錄** — 定期審閱記錄了的問題和答案的流程
- [ ] **標記回應** — 對標記錯誤答案行動的流程，包括文件庫更新
- [ ] **升級路徑** — 如果發生嚴重錯誤已定義

#### 關口 4 結果：通過 / 失敗

## 5. 紅 / 琥珀 / 綠決策

基於所有四個關口：

| 狀態 | 含義 | 決策 |
|------|------|------|
| 🟢 **綠** | 所有關口項目通過 | 進入試點 — 首先與有限觀眾構建和測試 |
| 🟡 **琥珀** | 具體項目失敗 — 已識別缺口 | 修復已識別缺口；構建前重新評估 |
| 🔴 **紅** | 關口 1 失敗，或多個關口 2/3 項目失敗 | 不要進入 — 首先解決根本原因 |

**琥珀或紅的最常見原因：**
- **無文件負責人** — 關口 2 / 關口 4
- **無版本日期** — 關口 2
- **多個版本** — 無清晰當前流通的副本，關口 2
- **文件庫中的個人資料** — 無法律審閱，關口 1
- **無 OCR 的掃描繁體中文** — 關口 2
- **自信錯誤答案** — 當來源未覆蓋問題時系統回答，關口 4
