# 人工智能用例分類評分卡

> [!quote] 目的：  
> 在投入時間和資源於任何人工智能項目之前，花 20 分鐘回答這些問題。  
> 評分告訴你是應該現在開始、先修復某些問題，還是完全停止。

**本評分卡用途：** 一個結構化工具，用於決定人工智能用例是否應該現在開始、作為小型試點開始、等待，或停止。

**本評分卡非：** 高分用例必然成功，或低分用例必然失敗的保證。這是一個思考工具，而非認證。最終決定仍由相關人員和機構作出。

---

## 1. 基本用例描述

首先完成本節。如果你無法清晰回答所有欄位，該用例尚未準備好進行評分。

| 欄位 | 你的答案 |
|------|----------|
| **用例名稱** | |
| **機構** | 中小企業 / 教會 / 非政府組織 / 其他： |
| **負責人 / 倡導者** | |
| **人工智能協助什麼任務？** | |
| **誰將使用它？** | |
| **當前的痛點或問題** | |
| **當前的人手流程** | |
| **期望的改進** | 時間 / 質素 / 一致性 / 成本 / 其他： |
| **這能否是簡單的工作流程而非人工智能？** | 是 / 否 / 不確定 |

---

### 如何評分

誠實回答每個問題。使用下方的評分指南。最後將每節總分相加。

| 分數 | 含義 |
|------|--------|
| **2** | 是，已清晰處理 — 無疑慮 |
| **1** | 部分處理或不確定 |
| **0** | 未處理、未知，或適用紅旗 |

**最終分數解讀：**

| 總分 | 決定 |
|------|------|
| 14–17 | ✅ **綠色：開始小型試點** — 條件良好 |
| 10–13 | ⚠️ **琥珀色：先修復** — 處理差距，然後重新評分 |
| 6–9 | 🔴 **危險：未準備好** — 重大差距；暫時不要開始 |
| 0–5 | ⛔ **紅色：停止** — 根本性問題；人工智能現時不是正確路徑 |

## 2. 3P：安全使用評估（0–6 分）

### P1 · 目的（0–2 分）
**這個人工智能用例的目的有多清晰？**

| 分數 | 情況 |
|------|------|
| **2** | 任務界限清晰：我們確切知道人工智能將做什麼、誰審核輸出，以及成功是什麼樣子 |
| **1** | 任務部分定義，但某些角色、界限或成功標準仍不清晰 |
| **0** | 目的模糊（「使用人工智能改善營運」），或人工智能被考慮是因為其他人正在使用它 |

**P1 紅旗 — 如適用任何一項，評分 0：**
- [ ] **模糊任務** — 僅描述為「使用人工智能改善我們的工作」
- [ ] **未命名審核者** — 未指定人工審核者
- [ ] **成功不可衡量** — 無法用一句可衡量的句子描述成功
- [ ] **人員決策** — 任務涉及人員的資格、獲取或福利

### P2 · 權限（0–2 分）
**我們對允許與人工智能一起使用的資料了解多少？**

| 分數 | 情況 |
|------|------|
| **2** | 我們已檢查《個人資料（私隱）條例》合規性；資料已匿名化或明確允許；不涉及敏感個人資料 |
| **1** | 我們已考慮資料權限，但尚未正式檢查《個人資料（私隱）條例》；可能涉及某些敏感資料 |
| **0** | 我們未考慮資料權限；或涉及敏感個人、牧養、人力資源或受規管資料 |

**P2 紅旗 — 如適用任何一項，評分 0：**
- [ ] **未檢查《個人資料（私隱）條例》** — 敏感個人資料將涉及而無《個人資料（私隱）條例》評估
- [ ] **工具未獲批准** — 未檢查資料條款
- [ ] **人員決策** — 任務涉及人員的資格、獲取或福利

**香港關口 — 繁體中文可讀性：**
- [ ] **繁體中文文件？** — 是否為打字數字格式（非掃描圖像）？（未測試的掃描繁體中文，尤其是手寫 = 自動紅色。測試並解決問題前不要繼續。）

> [!warning] 使用圖像會引入原生文本沒有的「隱藏」風險：  
> - **無聲幻覺：** 人工智能工具可能在未告知用戶的情況下「修復」混亂的手寫或模糊的繁體中文字符，可能改變文件的含義。  
> - **驗證負擔：** 當來源是圖像時，人工審核員必須更努力地將輸出與圖像來源交叉參考。

### P3 · 證明（0–2 分）
**我們能否驗證人工智能輸出並對其負責？**

| 分數 | 情況 |
|------|------|
| **2** | 人工審核已內建於工作流程中，在任何輸出到達任何人之前；我們可以解釋和審核人工智能做了什麼 |

| **0** | 未計劃人工審核步驟；或輸出在無審核的情況下直接到達外部方 |

- [ ] **直接到外部** — 輸出在無任何審核關口的情況下到達外部方

## 3. 3R：項目成功評估（0–6 分）

### R1 · 正確的問題（0–2 分）
**人工智能真的是這個問題的正確解決方案嗎？**

| 分數 | 情況 |
|------|------|
| **2** | 人工智能解決真實、具體、重複出現的痛點；已考慮替代方案，人工智能對此任務明顯更好 |
| **1** | 人工智能可能在此有用，但案例尚未測試；我們不確定更簡單的工具是否可行 |
| **0** | 人工智能被提議而無清晰的問題分析；或真正問題是流程或人員問題，而非工具問題 |

**幫助評分 R1 的診斷問題：**
- **一句話？** — 這解決什麼確切問題？
- **當前變通方法？** — 這個問題目前如何處理？什麼會出錯？
- **更簡單的解決方案？** — 更好的試算表、模板或標準作業程序能否在無人工智能的情況下解決這個問題？
- **涉及反對者？** — 機構中誰會反對這個，你是否已將他們納入？

**R1 紅旗 — 如適用任何一項，評分 0：**
- [ ] **模糊問題** — 「使用人工智能改善我們的工作」不是用例

*我的 R1 分數：* ___

### R2 · 就緒（0–2 分）
**我們是否準備好推進 — 跨越資料、機構、流程和管治？**

> [!note] 為何「就緒」涵蓋的不僅是資料：  
> 大多數人工智能項目失敗不是因為技術不好，而是因為其他方面未就緒：資料混亂、團隊未為變革做好準備、現有流程無處容納人工智能輸出，或無人思考誰負責。這個問題在承諾之前檢查所有四個就緒維度。

| 分數 | 情況 |
|------|------|
| **2** | 所有四個維度已處理：資料已整理且允許；人員已為變革做好準備；流程已設計以接收人工智能輸出；問責和管治已到位 |
| **1** | 大多數維度已處理，但一兩個有差距需要在試點期間注意 |
| **0** | 一個或多個維度有重大差距 — 資料不可用、人員未準備、流程未定義，或管治缺失 |

**R2 紅旗 — 如適用任何一項，評分 0：**
- [ ] **資料不可用** — 來源文件混亂、過時、不完整，或無法機器讀取
- [ ] **未命名負責人** — 此項目無負責人或贊助者

#### R2a — 資料就緒

| 檢查 | 狀態 |
|------|------|
| **原生數字文本** — 可搜尋，不僅是文本圖片 | 通過 / 失敗 |
| **繁體中文圖像可靠性** — 如為掃描/手寫，已測試準確性 | 通過 / 失敗 |
| **格式一致** — 來源間的命名和結構 | 通過 / 失敗 |
| **《個人資料（私隱）條例》通過** — 無敏感個人資料；原則 3 檢查已完成 | 通過 / 失敗 |
| **足夠完整** — 對於預期任務 | 通過 / 失敗 |
| **有權使用** — 此資料用於人工智能處理 | 通過 / 失敗 |

*如 2 行或以上失敗：資料未就緒。僅此一項可能評分 R2 = 0。*

#### R2b — 機構就緒

| 檢查 | 狀態 |
|------|------|
| **領導層批准** — 正式批准此用例 | 通過 / 失敗 |
| **命名問責人** — 負責人負責人工智能工作流程和輸出 | 通過 / 失敗 |
| **最終用戶已準備** — 職員參與並準備好變革 | 通過 / 失敗 |
| **反對者已納入** — 已識別並納入，而非繞過 | 通過 / 失敗 |
| **培訓已計劃** — 為最終用戶提供導向 | 通過 / 失敗 |

*機構就緒經常是真正的瓶頸。技術很少是。*

#### R2c — 流程就緒

| 檢查 | 狀態 |
|------|------|
| **工作流程已映射** — 我們知道人工智能輸出將落在何處 | 通過 / 失敗 |
| **流程已重新設計** — 包括人工智能作為起草步驟，並有人工審核 | 通過 / 失敗 |
| **錯誤路徑已定義** — 我們知道當人工智能產生錯誤時會發生什麼 | 通過 / 失敗 |
| **角色已分配** — 起草者、審核者和批准者已命名 | 通過 / 失敗 |

#### R2d — 管治就緒

| 檢查 | 狀態 |
|------|------|
| **政策已到位** — 人工智能使用政策存在或正在採用，於上線前 | 通過 / 失敗 |
| **升級路徑** — 如人工智能產生有害或錯誤內容，有清晰路徑 | 通過 / 失敗 |
| **質素標準** — 負責人能夠判斷什麼樣的輸出是好的 | 通過 / 失敗 |
| **審核計劃** — 試點後審核和改進工作流程的計劃 | 通過 / 失敗 |

*我的 R2 分數：* ___

### R3 · 現實的期望（0–2 分）
**時間、成本、精力和預期結果是否已誠實評估？**

| 分數 | 情況 |
|------|------|
| **2** | 清晰、可衡量的成功標準已定義；時間和資源估計有根據；我們接受人工智能輸出需要審核 |
| **1** | 粗略的成功標準但無堅實的資源估計；預期審核負擔但未建模 |
| **0** | 成功模糊；或預期人工智能在無人工審核的情況下工作；或承諾變革性結果而無證據 |

**R3 = 0 的警告信號：**
- **「節省 50% 時間」** — 無基線證據
- **「只需插入即可」** — 假設它在無流程設計的情況下工作
- **「供應商說簡單」** — 無獨立驗證
- **工具安裝完成** = 成功 — 不衡量實際成果
- **無基線** — 無當前指標可比較改進

**R3 紅旗 — 如適用任何一項，評分 0：**
- [ ] **無基線（定量案例）** — 無當前指標可比較時間、成本或績效改進
- [ ] **未定義價值（定性案例）** — 無清晰方式判斷輸出是否更好（例如清晰度、一致性、風險）
- [ ] **未命名負責人** — 此項目無負責人或贊助者
- [ ] **完全自動化** — 未計劃人工審核

## 4. 實際適配度評估（0–5 分）

**注意：** 第 4 節最高 5 分，總可能分數為 17 分。

### F1 · 風險等級（0–2 分）
**如果人工智能在此用例中產生錯誤，會有多嚴重？**

| 分數 | 情況 |
|------|------|
| **2** | 低風險：錯誤容易捕捉和糾正；無外部方受影響；無敏感內容 |
| **1** | 中風險：錯誤可能令機構尷尬或需要糾正努力；某些外部可見性 |
| **0** | 高風險：錯誤可能傷害人員、造成法律風險、損害牧養關係，或違反規例 |

**F1 紅旗 — 如適用任何一項，評分 0：**
- [ ] **牧養內容** — 用例涉及牧養輔導或靈性指導

- [ ] **大規模個人資料** — 大規模敏感個人資料
- [ ] **無審核關口** — 輸出在無人工審核的情況下到達外部
- [ ] **專業資格** — 任務需要法律、醫療或財務專業知識

## 5. 建議的起始模式

哪種起始模式最合適？勾選一項。

- [ ] **起草助理** — 人工智能產生初稿；人手編輯並發送
- [ ] **摘要助理** — 人工智能濃縮文件；人手驗證
- [ ] **內部問答助理** — 人工智能從批准文件回答問題；人手處理例外
- [ ] **翻譯 / 改寫** — 人工智能產生版本；合格人工審核
- [ ] **結構化提取** — 人工智能從文件提取欄位；人手在記錄前驗證
- [ ] **會議回顧** — 人工智能產生草稿摘要；與會者驗證
- [ ] **尚未適合** — 用例需要更多準備

## 7. 試點設計（如決定推進，請填寫）

與決定日誌一起完成本節。保留副本與項目記錄一起存檔。

設計良好的試點必須涵蓋以下各項：

- [ ] **範圍** — 一個具體、有界限的任務（非「我們所有的通訊」）
- [ ] **持續時間** — 最多 2–4 週
- [ ] **容量** — 擴展前 5–10 個真實輸出
- [ ] **指定審核者** — 在使用前閱讀每個人工智能輸出
- [ ] **審核點** — 在推進前需要人工審核的指定檢查點
- [ ] **成功指標** — 開始前定義
- [ ] **停止條件** — 什麼會使我們停止試點？
- [ ] **簽署人** — 誰在更廣泛推廣前批准？
- [ ] **退出條件** — 例如「如錯誤率 > 20%，我們停止」
- [ ] **記錄保存** — 人工智能產生什麼及什麼被更改的日誌

## 8. 避免從這些開始的用例

特別是對於教會和非政府組織 — 不要從這些開始：

- **牧養人工智能** — 通過人工智能進行輔導、祈禱事工或靈性指導
- **神學機器人** — 呈現為權威的問答機器人
- **自動化成員回應** — 未經逐則人工審核
- **人員決策** — 護理轉介、財務協助、義工適合性，或職員事項
- **成員個人資料** — 輸入任何公共人工智能工具
