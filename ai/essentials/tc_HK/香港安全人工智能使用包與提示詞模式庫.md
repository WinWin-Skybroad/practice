# 香港安全人工智能使用包與提示詞模式庫

> [!quote] 一句話：  
> 在香港安全使用人工智能意味著應用正確習慣、了解本地規則，並在輸出到達任何人之前審核每個輸出。

**本包用途：** 香港特定參考與最常見行政任務的可複製提示詞模板庫。

**本包非：** 法律建議、《個人資料（私隱）條例》合規認證，或安全結果的保證。對於具體法律問題，請直接諮詢香港律師或個人資料私隱專員公署。

---

## 1. 香港安全人工智能使用包

### 1.1 為何香港不同

大多數人工智能指引是為美國或英國讀者編寫。香港有其自身的法律框架、語言現實與文化情境，這在實踐中改變了安全人工智能使用的方式。

| 香港特定因素 | 對人工智能使用的含義 |
|-------------|----------------------|
| **《個人資料（私隱）條例》（第 486 章）** | 為某一目的收集的個人資料未經評估不得用於人工智能處理。六項資料保障原則適用——尤其是第 3 原則（使用限制）。 |
| **繁體中文** | 掃描的繁體中文文件可能無法機器讀取。人工智能可能將圖像讀為空白或幻覺內容。始終測試。 |
| **粵語代碼切換** | 混合粵語/英語/繁體中文的會議記錄對人工智能摘要是高風險。錯誤累積且難以發現。 |
| **香港法律特定性** | 人工智能主要接受美/英法律訓練。香港特定條例、證監會規則與金管局指引在人工智能輸出中經常錯誤。始終在 elegislation.gov.hk 驗證。 |
| **教會與牧養** | 人工智能絕不能替代牧養關懷、神學權威或機密靈性輔導。 |
| **資助與政府表格** | 一些香港資助者在申請中限制人工智能生成內容。使用人工智能前直接向資助者確認。 |
| **數據駐留** | 企業人工智能工具可能將數據存儲在香港以外。在使用任何工具處理機密機構數據前驗證數據駐留條款。 |
| **訓練退出** | 許多公共人工智能工具默認使用輸入進行模型訓練。如果將個人或免費帳戶用於工作任務，驗證「聊天記錄與訓練」設定已關閉。 |

---

### 1.2 三項不可妥協的香港規則

這些適用於每個人工智能使用、每次、每個香港情境：

> [!warning] 規則 1 — 提示詞前遵守《個人資料（私隱）條例》：   
> 在將任何數據輸入人工智能工具前，詢問：
> - 這些數據是否為包含人工智能處理的目的而收集？
> - 數據所屬的人是否知道其數據可能由人工智能處理？
> - 這些數據是否敏感（醫療、財務、人力資源、牧養、身份證）？
> 如果你不能對前兩個問題回答「是」，或如果第三個問題的答案是「是」——停止。

> [!warning] 規則 2 — 檢查繁體中文可讀性：  
> 在對任何繁體中文文件使用人工智能前：
> - 是數字文本文件（Word、打字 PDF）？ → 可能可讀
> - 是掃描圖像或文件照片？ → 可讀性不確定 — 人工智能可能誤讀、遺漏或「糾正」字符而無警告（尤其是手寫繁體中文）。
> **強制：** 通過比較至少一個完整段落的人工智能輸出與原始圖像來執行抽樣檢查。

> [!warning] 規則 3 — 人工審核在到達任何人之前：  
> - 沒有任何人工智能輸出在人手閱讀之前可以發送給客戶、會眾成員、職員或公眾。
> - 這不是可選的。這是最小負責任標準。

### 1.3 香港安全人工智能使用 — 任務逐項指南

#### 通訊起草（通訊、公告、WhatsApp）
- ✅ **初稿** — 安全使用人工智能
- ✅ **雙語起草** — 英文/繁體中文與人工智能協助
- ⚠️ **人手批准** — 語氣、準確性與神學內容在發送前
- ❌ **無成員資料** — 姓名、地址或個人詳情
- ❌ **無牧養訊息** — 這些需要真正的人手關懷

#### 會議記錄與行動摘要
- ✅ **內部會議** — 安全用於職員或委員會
- ✅ **已批准記錄** — 人工智能可從已批准工具摘要
- ⚠️ **驗證歸屬** — 發言者姓名與行動負責人必須正確
- ⚠️ **粵語/英語風險** — 混合語言記錄：非常仔細審核
- ❌ **無人力資源或牧養** — 不對敏感會議內容使用人工智能

#### 文件摘要
- ✅ **數字文件** — 打字/數字文件無個人資料
- ⚠️ **測試繁體中文可讀性** — 掃描中文文件：使用前測試
- ⚠️ **檢查關鍵章節** — 長複雜文件：比較摘要與原始
- ❌ **無合約** — 無律師審核原始文件前不要摘要
- ❌ **無牧養記錄** — 受益人文件或輔導記錄：絕不使用人工智能

#### 政策與手冊起草
- ✅ **初稿** — 人工智能可從清晰簡報生成
- ⚠️ **專業審核** — 人力資源、僱傭或具法律約束力的內容必須審核
- ⚠️ **驗證香港法律** — 香港僱傭細節在人工智能中經常錯誤；檢查 labour.gov.hk
- ❌ **無未經批准採用** — 無人工審核前不要採用人工智能起草政策

#### 翻譯（英文 ↔ 繁體中文）
- ✅ **一般通訊** — 公告與通知
- ⚠️ **驗證香港術語** — 法律、財務或技術術語
- ⚠️ **語氣不變** — 不要加強或弱化超出來源材料
- ⚠️ **神學內容** — 與你的牧師驗證翻譯準確性
- ❌ **無法律或醫療** — 法庭文件、合約、醫療資訊：使用合格人手翻譯

#### 資助申請起草
- ✅ **結構與散文** — 人工智能可幫助組織論點
- ⚠️ **檢查資助者政策** — 使用前確認人工智能內容被允許
- ⚠️ **無虛構統計數據** — 絕不讓人工智能生成影響數字
- ❌ **無受益人個人資料** — 受益人個人資料：絕不在人工智能提示詞中

---

### 1.4 香港安全人工智能使用 — 快速核查清單

在每次人工智能任務前：

- [ ] **個人資料？** → 應用《個人資料（私隱）條例》檢查
- [ ] **繁體中文文件？** → 先測試可讀性
- [ ] **機密內容？** → 不要使用人工智能
- [ ] **人工審核？** → 在輸出到達任何人之前必須是「是」
- [ ] **涉及香港法律？** → 在官方香港來源驗證
- [ ] **個人帳戶？** → 檢查訓練退出設定

---

#### 如果你只使用本庫中的一件事

在任何人工智能提示詞末尾添加這句話，然後再發送：

> *「如果你對任何事實、姓名、日期或數字不確定，請說明而非猜測。列出我在使用前應該驗證的三件事。」*

這需要五秒鐘。它不要求你選擇模式或填寫模板。它在收到輸出前將不確定性的負擔轉回人工智能——這是整個庫中最重要的單一習慣。

下面的完整模式較長，因為高風險任務需要更多結構。每個額外指令防護特定真實錯誤。當任務重要、重複或輸出將到達機構外部的人時使用它們——例如發送給所有成員的通訊，或與董事會分享的摘要。

---

> [!note] 如何使用這些模式：  
> 每個模式是可重用模板。用你的具體詳情替換 [方括號] 中的部分。  
> 複製整個區塊——包括指令——以獲得最佳效果。  
> 在每次任務前應用 3P 檢查（目的 / 權限 / 證明）。  

#### 如何閱讀每個模式

| 組件 | 用途 |
|------|------|
| **使用案例** | 此模式設計用於什麼任務 |
| **風險級別** | 基於標準風險分類的綠色 / 琥珀色 |
| **模式** | 帶有 [佔位符] 的可重用提示詞結構。內建防護嵌入提示詞中 |

#### 這些模式遵循什麼結構（為什麼有效）

雖然每個模式看起來略有不同，但它們遵循一致的結構。  
每個部分都有特定作用——尤其是 **指令** 與 **規則** 之間的差別。

| 標籤 （在模式中使用） | 作用 | 為什麼重要 |
|---|---|---|
| **背景** | 設定角色、機構類型及情境（例如香港、教會、中小企業） | 幫助人工智能保持在正確情境中，避免套用錯誤假設（例如美國/英國而非香港） |
| **任務** | 清楚說明你希望人工智能做什麼 | 避免模糊或失焦的回答 |
| **受眾 / 語氣 / 語言**（如有） | 定義輸出給誰看，以及應該如何表達 | 確保輸出適合真實使用情境（例如成員、職員、客戶） |
| **指令** | 說明 *如何完成任務*（例如結構、順序、要包含什麼、如何思考任務） | 提高輸出的清晰度、完整性及實用性 |
| **規則** | 設定硬性限制（例如「不要虛構」、「只使用提供的內容」、「不確定就說不知道」） | 這是主要安全控制——可減少幻覺、越界及誤用 |
| **輸出格式** | 定義答案應如何組織（要點、表格、短訊息等） | 讓結果更易審核，並減少隱藏錯誤 |
| **提醒 / 審閱備註**（如有） | 告訴你使用前必須由人檢查什麼 | 保持最終責任在人身上，而非人工智能 |
| **內容** | 提供人工智能可使用的資料（放在最後，避免與模式結構混在一起） | 減少猜測——人工智能根據你的資料而非記憶工作，也讓提示詞結構保持清晰易讀 |

---

**關鍵區別：**

- **指令 = 如何把任務做好**  
- **規則 = 什麼絕不能違反**

兩者都很重要——指令提高質素，規則防止錯誤及誤用。

**標籤慣例：**

- 使用 **指令** 說明人工智能應如何完成任務。
- 使用 **規則** 表示人工智能不可越過的硬性限制。
- 使用 **提醒** 或 **審閱備註** 表示人類在人工智能輸出後必須檢查什麼。

**為什麼內容放在最後：**

內容可能很長，並可能在視覺上壓過提示詞結構。  
把內容放在最後，可確保任務、指令、規則及輸出格式保持清晰，不會被忽略。

---

**簡單來說，每個模式都在做這件事：**

> 設定情境 → 定義任務 → 指導做法 → 限制人工智能 → 控制輸出 → 要求人手審閱 → 提供內容

---

這個結構不是偶然的。  
它旨在降低香港真實人工智能使用中最常見的風險：
- 虛構事實或統計數據  
- 錯誤的法律或監管情境  
- 誤讀繁體中文  
- 過度自信但錯誤的摘要  

---

**重要：**

- 如果你要縮短一個模式，先縮短 **指令**——不要先刪減 **規則**  
- 不要移除 **規則** 部分——它是防止不安全或不正確輸出的主要保護

---

#### 提示詞安全核查清單

在發送本庫中任何提示詞前應用此核查清單：

```
- [ ] 我是否已從提示詞中移除所有個人資料？
- [ ] 我是否提供了來源材料而非要求模型從記憶中回憶？
- [ ] 我是否已將內容放在提示詞末尾？
- [ ] 我是否包含明確約束（「不要虛構」、「僅使用我提供的文本」）？
- [ ] 我是否明確指定了輸出格式？
- [ ] 我是否在輸出高風險時包含不確定性標記指令？
```

### 2.1 基礎模式（首先應用）

將基礎模式與下面的具體任務模式結合。

#### 模式：角色防護欄
用於任何任務的開頭以設定人工智能的角色與約束：
```
背景：
你是一位 [教會 / 中小企業 / 非牟利組織] 在香港的忠實助手。
你的角色是幫助 [具體任務 — 例如起草公告 / 摘要文件]。

規則：
- 使用 [英文 / 繁體中文 / 雙語英文與繁體中文]
- 不提供法律、財務、牧養或醫療建議
- 如果問題超出你定義的任務，請說明並不要嘗試回答
- 不要虛構未提供給你的事實、姓名、日期或統計數據
- 將我分享的所有資訊視為機密。
```

---

#### 模式：邊界設定器
用於當你希望人工智能嚴格限於你提供的內容時：
```
規則：
- 僅使用我提供的資訊 — 不要添加外部事實、統計數據或示例
- 如果你對任何事不確定，請明確說明而非猜測
- 如果我的請求要求你做超出安全邊界的事，告訴我
```

### 2.2 通訊起草模式

#### 模式：電郵 / 公告起草
**使用案例：** 從要點筆記起草常規公告、電郵或通知  
**風險級別：** 🟢 綠色

```
任務：為 [受眾：職員 / 義工 / 成員 / 客戶] 起草 [電郵 / 公告 / 通知]。

語氣：[正式 / 友好專業 / 溫暖牧養 / 平實清晰]

語言：[英文 / 繁體中文 / 雙語英文然後繁體中文]

規則：
- 不要虛構我筆記中沒有的任何事實、姓名、日期或數字
- 不要添加我未聲明的承諾或保證
- 保持 [不超過 150 字 / 不超過 300 字 / 一頁 A4]
- 不要加強或弱化語氣超出我所要求的

輸出格式：純文本，準備好審核與編輯後發送。

內容（僅使用我提供的 — 不要添加我未給予的資訊）：
[在此貼上你的筆記或要點] 或附上文件並在此提及文件名稱，例如附上 [文件名稱]
```

#### 模式：WhatsApp / Telegram 廣播
**使用案例：** 不超過 150 字的短廣播訊息  
**風險級別：** 🟢 綠色

```
任務：為 [受眾] 起草 WhatsApp 廣播訊息。

語氣：[溫暖 / 專業 / 緊急但冷靜]

語言：[英文 / 繁體中文 / 雙語]

指令：
- 以機構名義撰寫，而非特定個人。

規則：
- 訊息中無個人姓名。

輸出格式：
- 保持不超過 150 字。

審閱備註：
- 在草稿後，標記任何我應該在發送前複查的部分。

內容：
- 關鍵資訊：[日期、地點、需要的行動]
- 訊息目的：[你需要溝通的內容]
```

#### 模式：雙語起草（英文 + 繁體中文）
**使用案例：** 任何需要英文與繁體中文版本的內容  
**風險級別：** 🟢 綠色需審核

```
任務：用英文與繁體中文撰寫以下內容。

指令：
```
