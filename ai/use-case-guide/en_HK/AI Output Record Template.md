# AI Output Record Template

## 1. Purpose and Scope

Use this template when AI output leaves the organisation, informs a decision, supports approval, or may need to be explained later.

The goal is not to create a heavy compliance archive. The goal is to make it possible to answer: **why does this output say that?**

## 3. How To Fill In This Record

Use enough detail so another responsible person can understand what happened, what source the AI output relied on, who checked it, what was corrected, and where the approved version is stored.

| Field | What to enter |
|---|---|
| **Use case** | The AI task performed, such as “Summarise Meeting Notes”, “Draft Communications”, “Produce Bilingual Versions”, or another use case from this guide. |
| **Date** | The date the AI output was created or reviewed. |
| **Owner** | The person responsible for the task or output. This may be different from the person who typed the prompt. |
| **Reviewer** | The person who checked the AI output before use. |
| **Reviewer role / authority** | Why this reviewer was the right person to check or approve the output, such as meeting chair, project owner, policy owner, communications lead, finance officer, or bilingual reviewer. |
| **AI tool used** | The AI tool or platform used, such as ChatGPT, Claude, Copilot, Gemini, or another approved tool. Include model or version if known. |
| **Prompt or task brief** | The actual prompt, or a safe link to where the prompt is stored. If the prompt contains confidential or personal information, do not copy it into this record unless this record is stored in the approved secure location. |
| **Source material used** | The documents, meeting notes, emails, policies, webpages, spreadsheets, transcripts, or other materials used as input or reference. |
| **Source version used** | The exact version, date, file name, document link, meeting date, policy version, webpage access date, or folder location of the source material used. This helps future reviewers find the same source later. |
| **Workflow used** | The review path followed before approval. Record the main steps, such as “AI draft → source check → owner revision → manager approval”. |
| **Key assumptions or limits** | Important assumptions, missing information, uncertainty, scope limits, or items the AI could not verify. |
| **Review checks completed** | The checks actually performed, such as source comparison, factual check, tone check, privacy check, bilingual meaning check, authority check, escalation check, or calculation check. |
| **Corrections made** | Changes made after review, including corrected facts, removed claims, changed wording, added caveats, or revised translation. |
| **Issues found** | Errors, missing context, unsupported claims, unclear wording, privacy concerns, authority concerns, or escalation items found during review. |
| **Escalation required?** | Mark “Yes” if the reviewer could not safely approve the output within their role, evidence, authority, competence, or approved process. |
| **Escalation owner / outcome** | If escalated, record who handled it and what decision was made. |
| **Approval decision** | The final review decision: approve as is, correct then approve, stop and escalate, or reject. |
| **Approver** | The person who approved the final output, if different from the reviewer. |
| **Approval date** | The date the final output was approved for use. |
| **Final approved output location** | Where the final version actually used is stored or published, such as a Google Drive link, SharePoint path, approved email draft, website URL, newsletter file, policy folder, or internal record system. This should point to the approved version, not an earlier AI draft. |

## 4. Examples For Non-Obvious Fields

### 4.1 Source version used

This means: which exact source did the AI rely on?

Do not write only “meeting notes”, “policy”, or “website”. Write enough detail so someone can find the same source later.

Examples:

- Board meeting notes — 2026-07-08
- Volunteer Policy v1.0, approved 2026-07-01
- Google Drive: /Policies/Privacy/Privacy Notice v2.docx
- Website page accessed 2026-07-12
- Transcript file: donor_briefing_2026-07-05.docx

---

### 4.2 Workflow used

This means: what review path did the output go through before it was approved or used?

Examples:

- AI draft → communications lead review → source check → approved for newsletter
- AI meeting summary → chair checked decisions and actions → unresolved item escalated
- AI translation → bilingual reviewer checked meaning and register → final approved
- AI policy answer → checked against approved policy → escalated to policy owner

---

### 4.3 Final approved output location

This means: where is the final version that people actually used?

This should not point to the raw AI draft unless the AI draft itself was approved unchanged.

Examples:

- Google Drive: /Newsletters/2026/July approved version.docx
- Mailchimp campaign: July donor update
- SharePoint: /Meeting Records/Approved summary 2026-07-08
- Website URL for the published page
- Approved Gmail draft sent on 2026-07-12

---

## 5. Handling Sensitive Information

Do not treat this record as a storage place for confidential information.

If the prompt, source, or output contains personal data, confidential data, donor data, beneficiary data, client data, HR information, pastoral/theological information, financial information, safeguarding material, or sensitive organisational material, store the material only in the approved internal location and record a safe reference link or file path.

Do not copy sensitive content into this template unless this template is itself stored and controlled in the approved secure location.

---

## 6. When To Keep This Record

Keep a record when the output:

- is sent externally
- affects people, money, rights, obligations, reputation, or policy
- is used in a grant, report, presentation, board paper, or official communication
- relies on source material that may change later
- required correction or escalation
- may be questioned by a funder, regulator, auditor, board member, client, donor, or responsible owner

---

## 7. Practical Rule

If the organisation cannot explain how an AI output came to say what it says, it is not ready to rely on that output for a real decision or external use.
