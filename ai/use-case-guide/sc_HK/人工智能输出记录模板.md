# 人工智能输出记录模板

## 1. 目的及范围

当人工智能输出会离开机构、影响决策、支持批准，或日后可能需要作出解释时，请使用本模板。

目的不是建立繁重的合规档案，而是让人能够回答：**为什么这项输出会这样说？**

## 3. 如何填写本记录

请提供足够资料，让另一名负责人能够了解发生了什么、人工智能输出依赖什么来源、由谁审核、作出了什么更正，以及已批准版本存放在哪里。

| 字段 | 应填写内容 |
|---|---|
| **应用案例** | 所执行的人工智能任务，例如“总结会议记录”、“草拟通讯”、“制作双语版本”，或本指南中的其他应用案例。 |
| **日期** | 创建或审核人工智能输出的日期。 |
| **负责人** | 对任务或输出负责的人。此人可能与输入提示词的人不同。 |
| **审核者** | 在使用人工智能输出前负责检查的人。 |
| **审核者角色 / 权限** | 说明为什么此审核者适合检查或批准输出，例如会议主席、项目负责人、政策负责人、通讯主管、财务人员或双语审核者。 |
| **使用的人工智能工具** | 所使用的人工智能工具或平台，例如 ChatGPT、Claude、Copilot、Gemini 或其他已批准工具。如知道模型或版本，也应记录。 |
| **提示词或任务简介** | 实际提示词，或安全链接至提示词的存放位置。如提示词包含机密或个人资料，除非本记录存放于已批准的安全位置，否则不要把该内容复制到本记录。 |
| **使用的来源材料** | 用作输入或参考的文件、会议记录、电邮、政策、网页、电子表格、誊本或其他材料。 |
| **使用的来源版本** | 所用来源材料的确切版本、日期、文件名称、文件链接、会议日期、政策版本、网页访问日期或文件夹位置。这有助日后审核者找到相同来源。 |
| **采用的工作流程** | 批准前所采用的审核路径。记录主要步骤，例如“人工智能草稿 → 来源核对 → 负责人修订 → 经理批准”。 |
| **主要假设或限制** | 重要假设、缺失资料、不确定性、范围限制，或人工智能无法核实的项目。 |
| **已完成的审核检查** | 实际进行的检查，例如来源比较、事实核对、语气检查、隐私检查、双语意思检查、权限检查、升级处理检查或计算核对。 |
| **已作出的更正** | 审核后作出的改动，包括更正事实、删除声称、修改措辞、加入限制说明或修订翻译。 |
| **发现的问题** | 审核期间发现的错误、缺失语境、缺乏依据的声称、不清晰措辞、隐私疑虑、权限疑虑或需要升级处理的事项。 |
| **是否需要升级处理？** | 如审核者因其角色、证据、权限、能力或已批准流程的限制而无法安全批准输出，标记为“是”。 |
| **升级处理负责人 / 结果** | 如已升级处理，记录由谁处理以及作出了什么决定。 |
| **批准决定** | 最终审核决定：原样批准、更正后批准、停止并升级处理，或拒绝。 |
| **批准者** | 如与审核者不同，记录批准最终输出的人。 |
| **批准日期** | 最终输出获批准使用的日期。 |
| **最终已批准输出位置** | 实际使用的最终版本存放或发布的位置，例如 Google Drive 链接、SharePoint 路径、已批准电邮草稿、网站网址、通讯文件、政策文件夹或内部记录系统。此位置应指向已批准版本，而不是较早的人工智能草稿。 |

## 4. 不明显字段的例子

### 4.1 使用的来源版本

意思是：人工智能依赖的是哪一个确切来源？

不要只写“会议记录”、“政策”或“网站”。应提供足够资料，让其他人日后能找到相同来源。

例子：

- 董事会会议记录 — 2026-07-08
- 志愿者政策 v1.0，于 2026-07-01 批准
- Google Drive：/Policies/Privacy/Privacy Notice v2.docx
- 网页访问日期：2026-07-12
- 誊本文件：donor_briefing_2026-07-05.docx

---

### 4.2 采用的工作流程

意思是：输出在获批准或使用前经过什么审核路径？

例子：

- 人工智能草稿 → 通讯主管审核 → 来源核对 → 批准用于通讯
- 人工智能会议记录摘要 → 主席核对决定及行动 → 未解决事项升级处理
- 人工智能翻译 → 双语审核者核对意思及语域 → 最终批准
- 人工智能政策回答 → 对照已批准政策核对 → 升级交由政策负责人处理

---

### 4.3 最终已批准输出位置

意思是：人们实际使用的最终版本在哪里？

除非原始人工智能草稿本身未经修改便获批准，否则此位置不应指向该原始草稿。

例子：

- Google Drive：/通讯/2026/七月批准版本.docx
- Mailchimp 推广活动：七月捐赠者更新
- SharePoint：/会议记录/已批准摘要-2026-07-08
- 已发布页面的网站网址
- 于 2026-07-12 发送的已批准 Gmail 草稿

## 5. 处理敏感资料

不要把本记录当作存放机密资料的地方。

如提示词、来源或输出包含个人资料、机密资料、捐赠者资料、受益人资料、客户资料、人力资源资料、牧养 / 神学资料、财务资料、安全保障材料或敏感机构资料，只可把材料存放于已批准的内部位置，并在本记录中记下安全的参考链接或文件路径。

除非本模板本身存放并受控于已批准的安全位置，否则不要把敏感内容复制到本模板。

---

## 6. 何时保留本记录

如输出符合以下情况，应保留记录：

- 对外发送
- 影响人、金钱、权利、义务、声誉或政策
- 用于资助申请、报告、简报、董事会文件或正式通讯
- 依赖日后可能改变的来源材料
- 曾需要更正或升级处理
- 日后可能受到资助方、监管机构、审计人员、董事会成员、客户、捐赠者或责任负责人的查问

---

## 7. 实用规则

如机构无法解释人工智能输出为什么会这样说，就未准备好依赖该输出作出真实决策或用于外部用途。
