# 草拟内部备忘录

## 1. 这个应用案例是什么

当您希望人工智能协助以下工作时，请使用本页：**草拟内部备忘录、内部通讯及行政通知**。

- 常见使用者：**教会、非营利机构、中小企业**。
- 批准级别：**一般可批准使用**。
- 需要人工审核：**是 — 发送者须对准确性负责**。
- 使用人工智能输出协助您草拟或检查工作。不要把它视为最终决定。

---

## 2. 这可能造成什么代价

内部备忘录可能把讨论、暂定建议或未解决问题变成看似已批准的决定。如果职员按该措辞行事，机构可能在有权负责人实际作出决定前便产生承诺、争议或执行工作。

---

## 3. 如何审核这个输出

批准人工智能输出前，请使用以下检查。不要只因输出读起来流畅便批准。

---

### 3.1 审核设置

1. 识别备忘录中每项被表述为已同意、已批准或已有结论的决定或立场。
2. 就每一项确认：谁有权作出这项决定，以及该人是否已正式作出决定？
3. 如实际上只有讨论，删除或限定任何暗示已达成共识的陈述。
4. 确认分发名单适合有关内容 — 不要超出该决定所需的范围。

---

### 3.2 批准前 — 一项检查

> **授权本备忘录的人是否已确认其中所述每项决定、政策变更及机构立场均已获正式批准 — 而不是只曾讨论？**

---

### 3.3 针对风险的审核检查

这些检查把 [[人工审核风险库]] 中的最低审核责任调整至本任务。

- **[[人工审核风险库#4.13 人工智能盲点|人工智能盲点]]：** 输出是否符合任务背后真实的人、真实情况、真实权限及真实后果，包括人工智能未获告知的默会情境，以及无法完全化约为提示词的生活经验或专业判断。
  - **就本应用案例而言：** 按实际内部受众、阶层、关系历史、近期决定、分发界线、发送者权限，以及职员把措辞视为正式决定或指示的后果，核查备忘录。
- **[[人工审核风险库#4.17 权限边界盲点|权限边界盲点]]：** 识别每项看似作出决定、批准、拒绝、承诺、警告、作出机构承担或表明正式立场的陈述。确认实际决策负责人，并删除、限定或升级处理超出发送者权限的措辞。
- **[[人工审核风险库#4.22 用户施压导致偏移|用户施压导致偏移]]：** 如使用者质疑审慎或有来源依据的答案，按现行已批准记录或责任负责人核实争议事项。不要只因修订后的人工智能措辞同意使用者，便把它视为更安全。

---

### 3.4 审核者决策

完成上述针对本任务的审核检查后，使用 [[审核者决策卡]] 选择一项结果：

- **原样批准**
- **更正后批准**
- **停止并升级处理**

如审核者欠缺本任务所需的角色、证据、权限、能力、来源访问权、语境或已批准流程，不要批准输出。

---

### 3.5 本任务的审核方法

以下审核指示已针对本任务调整。它们把 [[人工审核模式]] 中的可重用方法应用于这里涉及的实际来源、决定、人士及后果。

- **范围、权限及可行性审核：** 检查备忘录是否准确区分资料、建议、推荐、决定、批准及所需行动，并确认发送者对每一项是否有权限。
  - 留意：把建议呈现为决定、未经授权的承诺，或把可选行动写成强制要求的措辞。
  - 时机：分发前。
  - 审核者：备忘录负责人、决策负责人或获授权经理。

- **隐私 / 资料边界审核：** 检查来源、备忘录内容、附件及分发名单有否包含机密、人力资源、个人、财务、牧养或受限制资料。
  - 留意：不必要地包含敏感细节、错误分发群组，或受众范围超出来源所允许。
  - 时机：提示前及分发前。
  - 审核者：资料负责人、具人力资源 / 私隐意识的审核者或获授权发送者。

- **来源比较审核：** 将决定、状态、负责人、日期、条件及限制条件与已批准记录、会议记录或来源文件比较。
  - 留意：行动负责人错误、限制条件遗失、旧决定状态，或凭记忆补上的语境。
  - 时机：分发前。
  - 审核者：来源负责人或了解相关决定的人。

---

## 4. 何时应升级处理而不是批准

- 如输出影响法律、人力资源、财务、安全保障、医疗、法规、对外或高影响决定，而审核者没有确认安全使用所需的权限、能力、语境、来源访问权或已批准流程，应在使用前升级处理。
- 如输出可能约束机构、影响权利 / 义务，或看似官方批准，而审核者没有权限确认该效果，应升级处理。
- 每当涉及个人资料、人力资源、牧养、神学、医疗、财务、HKID（香港身份证号码）、受益人或机密资料，而审核者没有确认安全使用所需的权限、语境、来源访问权或已批准流程时，均应升级处理。
- 如摘要会影响决策、批准、资助、人力资源、法律或管治行动，而审核者未获授权或没有足够资料确认内容，应升级处理。

## 5. 提示前

使用人工智能处理本任务前，先检查以下基本事项：
- 目的清晰。
- 输入不包含不应输入工具的个人或机密资料。
- 有负责人可在使用人工智能输出前检查它。
- 任务没有要求人工智能作出决定、提供专业意见或充当最终权威。

- 确认本任务符合批准级别：**一般可批准使用**。
- 确认预定审核者可以完成所需人工审核：**是 — 发送者须对准确性负责**。

---

## 6. 人工智能盲点重点

**风险重点：** 权限讯号误读及用户施压导致偏移

**提示词重点：** 提示前，向人工智能提供备忘录目的、受众、发送者权限、已批准决定状态、机密界线、分发限制，以及尚未决定的事项。指示它不要因使用者施压而改用更肯定的措辞，除非有已批准决定或责任负责人支持。

**人工审核重点：** 审核者应检查备忘录是否听起来像超出已批准内容的决定、承诺、警告或正式立场。确认分发范围、内部敏感事项，以及使用者提出质疑后人工智能作出的任何修订。

**较深入的盲点审核：** 如备忘录涉及近期决定、内部张力、阶层、人员历史，或需要具机构职权的审核者处理的事项，请沿 [[如何使用本指南#6.1 Win.Win 人工智能盲点指南|Win.Win 人工智能盲点指南路径]] 进行。

**不要只依赖：** 专业语气。备忘录可以听起来清晰而正式，同时暗示实际不存在的权限或批准。

## 8. 主要风险

- **[[风险分类#3.6 权限 / 范围 / 承诺|权限 / 范围 / 承诺]]：[[人工审核风险库#4.17 权限边界盲点|权限边界盲点]]（高）** — 收到内部备忘录的职员会把它视为机构决定。人工智能会以具权威性的陈述方式草拟备忘录，因为这正是该格式的特性。这种风格所暗示的权限与实际是否存在权限无关。讨论变成决定、选项变成承诺、建议变成政策 — 不是因为任何人有此意图，而是因为备忘录格式暗示事情已定案。只检查专业程度而不核查所述权限是否准确的审核者，可能无法察觉这点。

---

## 9. 其他需注意风险

- **[[风险分类#3.11 人工智能盲点 / 语境风险|人工智能盲点 / 语境风险]]：[[人工审核风险库#4.22 用户施压导致偏移|用户施压导致偏移]]（中）** — 如使用者有把握地质疑谨慎答案，人工智能可能在没有新可靠证据下软化或推翻答案。同意使用者并不是核实。
- **[[风险分类#3.6 权限 / 范围 / 承诺|权限 / 范围 / 承诺]]：权限讯号误读（高）** — 人工智能可能不了解职员如何解读阶层、语气、时机及隐含指示。备忘录可能听起来像实际未获授权的决定、承诺、警告或管理层立场。
- **[[风险分类#3.4 隐私 / 机密性 / 资料边界|隐私 / 机密性 / 资料边界]]：机密内容外泄（高）** — 内部不代表低敏感度。备忘录可能包含人力资源事项、财务资料或政策敏感内容。人工智能处理这些内容可能令资料超出原定边界而外泄。
- **[[风险分类#3.4 隐私 / 机密性 / 资料边界|隐私 / 机密性 / 资料边界]]：发布范围错误（中）** — 除非提供现行机构角色、分发规则或相关语境，否则不应假定人工智能知道适当的收件人。它可能产生范围、语言或内容只适合某一受众的文件，却透过例行流程分发给更广泛群组。
- **[[风险分类#3.3 语境 / 细微差别 / 压缩|语境 / 细微差别 / 压缩]]：语境差距 — 相关审核风险：[[人工审核风险库#4.14 未成文语境差距|未成文语境差距]]（中）** — 人工智能不知道内部机构历史、先前决定或人际互动。逻辑上看似正确的备忘录，可能在具体情境中并不恰当。

## 11. 其他缓解措施

- 人工审核应由能批准范围及承诺的人进行，而不是只由检查拼写或语法的人进行。
- 如敏感资料已输入未获批准的工具，审核输出无法撤销泄露。应按照隐私 / 事故处理流程升级处理。
- 人类审核者可能从记忆填补缺口；应保持来源文件可见，并明确标示不确定事项。
