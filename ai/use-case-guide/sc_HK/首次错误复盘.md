# 首次错误复盘

## 1. 目的及范围

第一次出现人工智能错误时，不要只叫审核者再小心一点。

要把错误视为工作流程提供的信息。

---

## 2. 复盘设计，而不只是复盘个人

请问：

1. 这个应用案例是否适合使用人工智能协助？
2. 提示词是否足够清楚，适合这项任务？
3. 来源资料包是否最新、已批准及完整？
4. 审核者是否与特定风险相配？
5. 任务量是否令审核过于粗疏？
6. 升级处理路径是否清楚而且可用？
7. 输出是否涉及某项风险，令应用案例应由已批准改为有条件批准、尚未适合或停止？

---

## 3. 常见设计原因

| 现象 | 可能的设计原因 |
|---|---|
| 错误事实通过审核 | 来源过时、不完整，或没有对照正确记录核对。 |
| 出现敏感内容 | 来源资料包或提示词没有界定必须排除的内容。 |
| 审核者在权限范围外批准 | 升级处理路径或批准界线不清楚。 |
| 同一错误重复出现 | 更正没有回写至提示词、模板、工作流程或审核方法。 |
| 审核变成快速略读 | 工作量增加，但没有相应审核能力或抽样规则。 |
| 使用者提出质疑后，人工智能答案改变 | 没有对照来源检查用户施压导致偏移。 |
| 把人工智能检查人工智能当作核实 | 缺少独立来源核对。 |

---

## 4. 复盘后

决定是否：

- 保持应用案例已批准，但修正工作流程
- 在修正缺口前改为有条件批准
- 暂停试点
- 把应用案例升级交由责任负责人处理
- 因目前机构无法控制风险而停止该应用案例

---

## 5. 实用规则

第一个错误是一个设计信号。应利用它改善工作流程，避免同一弱点以另一种形式再次出现。
