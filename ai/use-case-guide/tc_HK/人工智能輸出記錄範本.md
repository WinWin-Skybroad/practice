# 人工智能輸出記錄範本

## 1. 目的及範圍

當人工智能輸出會離開機構、影響決策、支援批准，或日後可能需要作出解釋時，請使用本範本。

目的不是建立繁重的合規檔案，而是讓人能夠回答：**為甚麼這項輸出會這樣說？**

## 3. 如何填寫本記錄

請提供足夠資料，讓另一名負責人能夠了解發生了甚麼、人工智能輸出依賴甚麼來源、由誰審核、作出了甚麼更正，以及已批准版本存放在哪裏。

| 欄位 | 應填寫內容 |
|---|---|
| **應用案例** | 所執行的人工智能任務，例如「總結會議記錄」、「草擬通訊」、「製作雙語版本」，或本指南中的其他應用案例。 |
| **日期** | 建立或審核人工智能輸出的日期。 |
| **負責人** | 對任務或輸出負責的人。此人可能與輸入提示詞的人不同。 |
| **審核者** | 在使用人工智能輸出前負責檢查的人。 |
| **審核者角色 / 權限** | 說明為甚麼此審核者適合檢查或批准輸出，例如會議主席、項目負責人、政策負責人、通訊主管、財務人員或雙語審核者。 |
| **使用的人工智能工具** | 所使用的人工智能工具或平台，例如 ChatGPT、Claude、Copilot、Gemini 或其他已批准工具。如知道模型或版本，也應記錄。 |
| **提示詞或任務簡介** | 實際提示詞，或安全連結至提示詞的存放位置。如提示詞包含機密或個人資料，除非本記錄存放於已批准的安全位置，否則不要把該內容複製到本記錄。 |
| **使用的來源材料** | 用作輸入或參考的文件、會議記錄、電郵、政策、網頁、試算表、謄本或其他材料。 |
| **使用的來源版本** | 所用來源材料的確切版本、日期、檔案名稱、文件連結、會議日期、政策版本、網頁存取日期或資料夾位置。這有助日後審核者找到相同來源。 |
| **採用的工作流程** | 批准前所採用的審核路徑。記錄主要步驟，例如「人工智能草稿 → 來源核對 → 負責人修訂 → 經理批准」。 |
| **主要假設或限制** | 重要假設、缺失資料、不確定性、範圍限制，或人工智能無法核實的項目。 |
| **已完成的審核檢查** | 實際進行的檢查，例如來源比較、事實核對、語氣檢查、私隱檢查、雙語意思檢查、權限檢查、升級處理檢查或計算核對。 |
| **已作出的更正** | 審核後作出的改動，包括更正事實、刪除聲稱、修改措辭、加入限制說明或修訂翻譯。 |
| **發現的問題** | 審核期間發現的錯誤、缺失語境、缺乏依據的聲稱、不清晰措辭、私隱疑慮、權限疑慮或需要升級處理的事項。 |
| **是否需要升級處理？** | 如審核者因其角色、證據、權限、能力或已批准流程的限制而無法安全批准輸出，標記為「是」。 |
| **升級處理負責人 / 結果** | 如已升級處理，記錄由誰處理以及作出了甚麼決定。 |
| **批准決定** | 最終審核決定：原樣批准、更正後批准、停止並升級處理，或拒絕。 |
| **批准者** | 如與審核者不同，記錄批准最終輸出的人。 |
| **批准日期** | 最終輸出獲批准使用的日期。 |
| **最終已批准輸出位置** | 實際使用的最終版本存放或發布的位置，例如 Google Drive 連結、SharePoint 路徑、已批准電郵草稿、網站網址、通訊檔案、政策資料夾或內部記錄系統。此位置應指向已批准版本，而不是較早的人工智能草稿。 |

## 4. 不明顯欄位的例子

### 4.1 使用的來源版本

意思是：人工智能依賴的是哪一個確切來源？

不要只寫「會議記錄」、「政策」或「網站」。應提供足夠資料，讓其他人日後能找到相同來源。

例子：

- 董事會會議記錄 — 2026-07-08
- 義工政策 v1.0，於 2026-07-01 批准
- Google Drive：/Policies/Privacy/Privacy Notice v2.docx
- 網頁存取日期：2026-07-12
- 謄本檔案：donor_briefing_2026-07-05.docx

---

### 4.2 採用的工作流程

意思是：輸出在獲批准或使用前經過甚麼審核路徑？

例子：

- 人工智能草稿 → 通訊主管審核 → 來源核對 → 批准用於通訊
- 人工智能會議紀錄摘要 → 主席核對決定及行動 → 未解決事項升級處理
- 人工智能翻譯 → 雙語審核者核對意思及語域 → 最終批准
- 人工智能政策回答 → 對照已批准政策核對 → 升級交由政策負責人處理

---

### 4.3 最終已批准輸出位置

意思是：人們實際使用的最終版本在哪裏？

除非原始人工智能草稿本身未經修改便獲批准，否則此位置不應指向該原始草稿。

例子：

- Google Drive：/通訊/2026/七月批准版本.docx
- Mailchimp 推廣活動：七月捐贈者更新
- SharePoint：/會議記錄/已批准摘要-2026-07-08
- 已發布頁面的網站網址
- 於 2026-07-12 發送的已批准 Gmail 草稿

## 5. 處理敏感資料

不要把本記錄當作存放機密資料的地方。

如提示詞、來源或輸出包含個人資料、機密資料、捐贈者資料、受益人資料、客戶資料、人力資源資料、牧養 / 神學資料、財務資料、安全保障材料或敏感機構資料，只可把材料存放於已批准的內部位置，並在本記錄中記下安全的參考連結或檔案路徑。

除非本範本本身存放並受控於已批准的安全位置，否則不要把敏感內容複製到本範本。

---

## 6. 何時保留本記錄

如輸出符合以下情況，應保留記錄：

- 對外發送
- 影響人、金錢、權利、義務、聲譽或政策
- 用於資助申請、報告、簡報、董事會文件或正式通訊
- 依賴日後可能改變的來源材料
- 曾需要更正或升級處理
- 日後可能受到資助方、監管機構、核數師、董事會成員、客戶、捐贈者或責任負責人的查問

---

## 7. 實用規則

如機構無法解釋人工智能輸出為甚麼會這樣說，就未準備好依賴該輸出作出真實決策或用於外部用途。
