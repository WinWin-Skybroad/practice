# 總結會議記錄

## 1. 這個應用案例是甚麼

當您希望人工智能協助**把會議筆記或會議記錄總結為結構化摘要**時，請使用本頁。

- 常見使用者：**教會、非牟利機構、中小企業**。
- 批准級別：**非機密情況下一般可批准使用**。
- 需要人工審核：**是 — 檢查準確性、歸因及行動負責人**。
- 使用人工智能輸出協助您草擬或檢查工作。不要把它視為最終決定。

---

## 2. 這可能造成甚麼代價

會議紀錄摘要可能把已討論或延期項目記錄為已批准、指派錯誤負責人、遺漏條件，或把未解決問題變成決定。如團隊未把摘要與原始筆記及會議實際權限比較便採取行動，機構可能作出未經授權的承諾，或需要撤回已開始的工作。

---

## 3. 如何審核這個輸出

批准人工智能輸出前，請使用以下檢查。不要只因輸出讀起來流暢便批准。

---

### 3.1 審核設定

1. 把原始會議筆記與人工智能摘要並排打開。
2. 對摘要中的每項決定、行動項目及行動負責人，在原始筆記中找出相應記錄，並確認狀態、負責人及範圍完全一致。
3. 特別留意延期項目、有條件批准，以及會議只有討論而沒有正式決定的任何項目。
4. 不要憑記憶審核摘要。出席會議的人最有可能遺漏這類錯誤，而不是最不可能。

---

### 3.2 批准前 — 一項檢查

> **是否已有出席本次會議的人在打開原始文件的情況下，把本摘要中的每項決定、行動項目及行動負責人與原始筆記比較 — 而不是憑記憶？**

---

### 3.3 針對風險的審核檢查

這些檢查把 [[人工審核風險庫]] 中的最低審核責任調整至本任務。

- **[[人工審核風險庫#4.2 內部人士盲點|內部人士盲點]]：** 把每項決定、限制、行動負責人、到期日、狀態、未解決問題及發布邊界與原始筆記或錄音比較。使用局外人測試：摘要必須讓沒有出席會議的讀者也能理解。
- **[[人工審核風險庫#4.4 自動化鬆懈|自動化鬆懈]]：** 即使較早摘要準確，也確認仍採用相同的完整來源比較及批准標準。指派具名審核者，不要因工作流程已成例行而減少核查。
- **[[人工審核風險庫#4.8 無法感知的缺失語境|無法感知的缺失語境]]：** 檢查先前決定、本地限制、關係情境、持份者敏感事項、資料質素疑慮或其他缺失事實，是否可能改變摘要的意思、發布範圍或所需行動。決定是否加入安全語境、保留僅供審核者使用的備註、向負責人核對或升級處理。
- **[[人工審核風險庫#4.9 先前語境悄然遺失|先前語境悄然遺失]]：** 確認當前指示及來源資料包仍包含會議目的、相關先前決定、術語、排除項目、來源限制、發布規則及批准邊界。把最終摘要與這些要求比較，不要依賴較早的聊天語境。
- **[[人工審核風險庫#4.12 無權批准|無權批准]]：** 把每項所述決定、批准、承諾、義務、期限、退款、政策立場或公開聲明與原始筆記及實際決策負責人核對。重新措辭被呈現為已批准決定的建議或提案。

---

### 3.4 審核者決策

完成上述針對本任務的審核檢查後，使用 [[審核者決策卡]] 選擇一項結果：

- **原樣批准**
- **更正後批准**
- **停止並升級處理**

如審核者欠缺本任務所需的角色、證據、權限、能力、來源存取權、語境或已批准流程，不要批准輸出。

---

### 3.5 本任務的審核方法

以下審核指示已針對本任務調整。它們把 [[人工審核模式]] 中的可重用方法應用於這裏涉及的實際來源、決定、人士及後果。

- **來源比較審核：** 把每項決定、提案、反對、延期、行動負責人、期限及批准狀態與原始筆記及任何已批准先前決定摘錄比較。
  - 留意：把討論變成協議、錯誤歸因、遺漏限制、以猜測解決不清晰負責人，或沒有來源便引入先前語境。
  - 時間：傳閱或用作正式會議記錄前。
  - 審核者：會議主席、記錄員，或對正式記錄負責的人。

- **以人工判斷為本的審核：** 檢查摘要是否符合實際參與者的理解，包括默認協議、關係情境、目前敏感事項，以及刻意沒有定稿或傳閱的事項。
  - 留意：文字上看似合理，但內部人士知道具有誤導性、不完整、不敏感或與會議實際運作不一致的摘要。
  - 時間：傳閱前。
  - 審核者：會議負責人，或具有足夠語境及身分的參與者。

- **私隱 / 資料邊界審核：** 決定每個版本及受眾可出現哪些敏感、人力資源、牧養、受益人、財務或機密內容。
  - 留意：沒有獲授權理由便把受限制細節帶入董事會、職員、義工或公開摘要。
  - 時間：提示前及每個版本傳閱前。
  - 審核者：資料負責人、會議主席、具人力資源 / 私隱意識的審核者或獲授權經理。

- **範圍、權限及可行性審核：** 確認摘要沒有把建議或討論變成獲授權決定或承諾。
  - 留意：無權批准、暗示已批准預算，或把行動指派至超出具名負責人角色的範圍。
  - 時間：摘要被視為正式記錄或指示前。
  - 審核者：決策負責人、會議主席或獲授權批准者。

## 4. 何時應升級處理而不是批准

- 如輸出影響法律、人力資源、財務、安全保障、醫療、法規、對外或高影響決定，而審核者沒有確認安全使用所需的權限、能力、語境、來源存取權或已批准流程，應在使用前升級處理。
- 如摘要會影響決策、批准、資助、人力資源、法律或管治行動，而審核者未獲授權或沒有足夠資料確認內容，應升級處理。
- 如來源本身不清晰、過時、缺失或與另一個已批准來源衝突，應升級處理。

---

## 5. 提示前

使用人工智能處理本任務前，先檢查以下基本事項：
- 目的清晰。
- 輸入不包含不應輸入工具的個人或機密資料。
- 有負責人可在使用人工智能輸出前檢查它。
- 任務沒有要求人工智能作出決定、提供專業意見或充當最終權威。
- 確認本任務符合批准級別：**非機密情況下一般可批准使用**。
- 確認計劃中的審核者能完成所需人工審核：**是 — 檢查準確性、歸因及行動負責人**。

## 6. 人工智能盲點重點

**風險重點：** 默認同意差距

**提示詞重點：** 提示前，向人工智能提供會議目的、摘要受眾、決策規則、行動負責人格式、批准流程，以及未解決項目是否必須維持未解決。要求它標記有關決定、批准、反對、延期及行動負責人的假設。

**人工審核重點：** 審核者應按筆記核對每項決定、行動負責人、期限、反對、延期及批准狀態。不要讓人工智能把討論變成協議，或把沉默變成批准。

**較深入的盲點審核：** 如摘要取決於是否真正達成討論、協議、反對、延期或正式批准，請沿 [[如何使用本指南#6.1 Win.Win 人工智能盲點指南|Win.Win 人工智能盲點指南路徑]] 進行。

**不要只依賴：** 會議紀錄摘要的整潔程度。整潔的行動清單可能隱藏未解決分歧或未獲批准的決定。

## 8. 主要風險

- **[[風險分類#3.3 語境 / 細微差別 / 壓縮|語境 / 細微差別 / 壓縮]]：[[人工審核風險庫#4.2 內部人士盲點|內部人士盲點]]（高）** — 審核人工智能會議紀錄摘要的人曾在會議現場。他們知道原意、知道同意了甚麼，也知道語境。當人工智能遺漏限制或誇大結論時，審核者會不自覺地從記憶中補正 — 因為他們知道應該有甚麼。摘要因此通過審核，但錯誤仍留給所有沒有出席會議、也沒有記憶填補缺口的其他讀者。這不是注意力失誤，而是可預期的位置失誤：最適合審核摘要的人，反而最難看見其中錯誤。

## 9. 其他需注意風險

- **[[風險分類#3.11 人工智能盲點 / 語境風險|人工智能盲點 / 語境風險]]：默認同意差距 — 相關審核風險：[[人工審核風險庫#4.14 未成文語境差距|未成文語境差距]]（高）** — 除非筆記寫得清楚，人工智能可能無法區分討論、支持、反對、延期及正式批准。會議中的人可能記得差異，但摘要仍必須按記錄核對。
- **[[風險分類#3.2 來源依據 / 證據|來源依據 / 證據]]：歸因混淆（高）** — 人工智能可能對調姓名或把行動項目指派給錯誤的人，尤其姓名相似或討論節奏很快時。認得姓名的審核者可能快速略過而錯失錯誤。
- **牧養 / 神學 / 聖經：資料越界（高）** — 同一次會議的筆記往往同時包含公開更新、內部營運事項，以及敏感的牧養 / 神學或人力資源項目。人工智能未必能按預定受眾及存取邊界安全而一致地分類這些內容。供廣泛傳閱的摘要可能包含只應發給特定人士的項目。
- **牧養 / 神學 / 聖經：缺乏責任歸屬的敏感細節（高）** — 如個人、牧養 / 神學或機密細節未提供給人工智能提示詞，必須由具名人士人手把它們加回適合相應受眾的正確版本。如沒有事先記錄隱去甚麼及由誰負責這一步驟，這項責任便會消失。
- **[[風險分類#3.3 語境 / 細微差別 / 壓縮|語境 / 細微差別 / 壓縮]]：先前會議的語境差距 — 相關審核風險：[[人工審核風險庫#4.14 未成文語境差距|未成文語境差距]]（中）** — 人工智能只知道當前提示詞中的內容，不知道先前會議作出的決定。摘要對本次會議在技術上可能準確，卻因缺少先前語境而具誤導性。
- **[[風險分類#3.6 權限 / 範圍 / 承諾|權限 / 範圍 / 承諾]]：[[人工審核風險庫#4.12 無權批准|無權批准]]（高）** — 審核者可能能夠核查摘要是否符合筆記，但仍沒有權限批准摘要所暗示的決定、承諾、管治行動或公開通訊。
- **[[風險分類#3.12 營運可行性 / 工作流程|營運可行性 / 工作流程]]：[[人工審核風險庫#4.4 自動化鬆懈|自動化鬆懈]]（中）** — 當會議紀錄摘要反覆產生時，因為以往人工智能摘要看似可靠，審核者可能逐漸停止按原始筆記核查每項決定、行動負責人及延期項目。
- **[[風險分類#3.3 語境 / 細微差別 / 壓縮|語境 / 細微差別 / 壓縮]]：[[人工審核風險庫#4.8 無法感知的缺失語境|無法感知的缺失語境]]（高）** — 先前決定、非正式限制、持份者敏感事項或其他事實等重要語境，可能未出現在筆記、提示詞或審核基礎中。審核者必須判斷缺失語境是否改變摘要的適切性、意思、風險或所需處理，以及應否安全加入、保留在僅供審核者使用的備註、向適當負責人核對或升級處理。
- **[[風險分類#3.3 語境 / 細微差別 / 壓縮|語境 / 細微差別 / 壓縮]]：[[人工審核風險庫#4.9 先前語境悄然遺失|先前語境悄然遺失]]（高）** — 在用於多份會議紀錄摘要的長對話中，使用者可能依賴很早之前說明的決定、限制、批准邊界或來源限制。如這些內容已不在產生摘要所用的即時指示或來源材料中，後續輸出可能遺漏或與之矛盾。

## 10. 要加入的提示詞強化

先從 Win.Win 人工智能必備的基礎提示詞模式開始。以下附加項已針對本任務調整。

只使用與實際情況相符的列。不要只因某項控制出現在 [[提示詞強化模式]] 便加入無關控制。對於主要須透過人工審核、已批准工具、專業檢查、其他緩解措施或升級處理的風險，不要建立提示詞附加項。

把來源材料、筆記、政策摘錄、數字及文件放在基礎提示詞最後的 **內容** 部分。
