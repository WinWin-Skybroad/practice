# 草擬內部備忘錄

## 1. 這個應用案例是甚麼

當您希望人工智能協助以下工作時，請使用本頁：**草擬內部備忘錄、內部通訊及行政通知**。

- 常見使用者：**教會、非牟利機構、中小企業**。
- 批准級別：**一般可批准使用**。
- 需要人工審核：**是 — 發送者須對準確性負責**。
- 使用人工智能輸出協助您草擬或檢查工作。不要把它視為最終決定。

---

## 2. 這可能造成甚麼代價

內部備忘錄可能把討論、暫定建議或未解決問題變成看似已批准的決定。如果職員按該措辭行事，機構可能在有權負責人實際作出決定前便產生承諾、爭議或執行工作。

---

## 3. 如何審核這個輸出

批准人工智能輸出前，請使用以下檢查。不要只因輸出讀起來流暢便批准。

---

### 3.1 審核設定

1. 識別備忘錄中每項被表述為已同意、已批准或已有結論的決定或立場。
2. 就每一項確認：誰有權作出這項決定，以及該人是否已正式作出決定？
3. 如實際上只有討論，刪除或限定任何暗示已達成共識的陳述。
4. 確認分發名單適合有關內容 — 不要超出該決定所需的範圍。

---

### 3.2 批准前 — 一項檢查

> **授權本備忘錄的人是否已確認其中所述每項決定、政策變更及機構立場均已獲正式批准 — 而不是只曾討論？**

---

### 3.3 針對風險的審核檢查

這些檢查把 [[人工審核風險庫]] 中的最低審核責任調整至本任務。

- **[[人工審核風險庫#4.13 人工智能盲點|人工智能盲點]]：** 輸出是否符合任務背後真實的人、真實情況、真實權限及真實後果，包括人工智能未獲告知的默會情境，以及無法完全化約為提示詞的生活經驗或專業判斷。
  - **就本應用案例而言：** 按實際內部受眾、階層、關係歷史、近期決定、分發界線、發送者權限，以及職員把措辭視為正式決定或指示的後果，核查備忘錄。
- **[[人工審核風險庫#4.17 權限邊界盲點|權限邊界盲點]]：** 識別每項看似作出決定、批准、拒絕、承諾、警告、作出機構承擔或表明正式立場的陳述。確認實際決策負責人，並刪除、限定或升級處理超出發送者權限的措辭。
- **[[人工審核風險庫#4.22 用戶施壓導致偏移|用戶施壓導致偏移]]：** 如使用者質疑審慎或有來源依據的答案，按現行已批准記錄或責任負責人核實爭議事項。不要只因修訂後的人工智能措辭同意使用者，便把它視為更安全。

---

### 3.4 審核者決策

完成上述針對本任務的審核檢查後，使用 [[審核者決策卡]] 選擇一項結果：

- **原樣批准**
- **更正後批准**
- **停止並升級處理**

如審核者欠缺本任務所需的角色、證據、權限、能力、來源存取權、語境或已批准流程，不要批准輸出。

---

### 3.5 本任務的審核方法

以下審核指示已針對本任務調整。它們把 [[人工審核模式]] 中的可重用方法應用於這裏涉及的實際來源、決定、人士及後果。

- **範圍、權限及可行性審核：** 檢查備忘錄是否準確區分資料、建議、推薦、決定、批准及所需行動，並確認發送者對每一項是否有權限。
  - 留意：把建議呈現為決定、未經授權的承諾，或把可選行動寫成強制要求的措辭。
  - 時機：分發前。
  - 審核者：備忘錄負責人、決策負責人或獲授權經理。

- **私隱 / 資料邊界審核：** 檢查來源、備忘錄內容、附件及分發名單有否包含機密、人力資源、個人、財務、牧養或受限制資料。
  - 留意：不必要地包含敏感細節、錯誤分發群組，或受眾範圍超出來源所允許。
  - 時機：提示前及分發前。
  - 審核者：資料負責人、具人力資源 / 私隱意識的審核者或獲授權發送者。

- **來源比較審核：** 將決定、狀態、負責人、日期、條件及限制條件與已批准記錄、會議記錄或來源文件比較。
  - 留意：行動負責人錯誤、限制條件遺失、舊決定狀態，或憑記憶補上的語境。
  - 時機：分發前。
  - 審核者：來源負責人或了解相關決定的人。

---

## 4. 何時應升級處理而不是批准

- 如輸出影響法律、人力資源、財務、安全保障、醫療、法規、對外或高影響決定，而審核者沒有確認安全使用所需的權限、能力、語境、來源存取權或已批准流程，應在使用前升級處理。
- 如輸出可能約束機構、影響權利 / 義務，或看似官方批准，而審核者沒有權限確認該效果，應升級處理。
- 每當涉及個人資料、人力資源、牧養、神學、醫療、財務、HKID（香港身份證號碼）、受益人或機密資料，而審核者沒有確認安全使用所需的權限、語境、來源存取權或已批准流程時，均應升級處理。
- 如摘要會影響決策、批准、資助、人力資源、法律或管治行動，而審核者未獲授權或沒有足夠資料確認內容，應升級處理。

---

## 5. 提示前

使用人工智能處理本任務前，先檢查以下基本事項：
- 目的清晰。
- 輸入不包含不應輸入工具的個人或機密資料。
- 有負責人可在使用人工智能輸出前檢查它。
- 任務沒有要求人工智能作出決定、提供專業意見或充當最終權威。

- 確認本任務符合批准級別：**一般可批准使用**。
- 確認預定審核者可以完成所需人工審核：**是 — 發送者須對準確性負責**。

## 6. 人工智能盲點重點

**風險重點：** 權限訊號誤讀及用戶施壓導致偏移

**提示詞重點：** 提示前，向人工智能提供備忘錄目的、受眾、發送者權限、已批准決定狀態、機密界線、分發限制，以及尚未決定的事項。指示它不要因使用者施壓而改用更肯定的措辭，除非有已批准決定或責任負責人支持。

**人工審核重點：** 審核者應檢查備忘錄是否聽起來像超出已批准內容的決定、承諾、警告或正式立場。確認分發範圍、內部敏感事項，以及使用者提出質疑後人工智能作出的任何修訂。

**較深入的盲點審核：** 如備忘錄涉及近期決定、內部張力、階層、人員歷史，或需要具機構職權的審核者處理的事項，請沿 [[如何使用本指南#6.1 Win.Win 人工智能盲點指南|Win.Win 人工智能盲點指南路徑]] 進行。

**不要只依賴：** 專業語氣。備忘錄可以聽起來清晰而正式，同時暗示實際不存在的權限或批准。

## 8. 主要風險

- **[[風險分類#3.6 權限 / 範圍 / 承諾|權限 / 範圍 / 承諾]]：[[人工審核風險庫#4.17 權限邊界盲點|權限邊界盲點]]（高）** — 收到內部備忘錄的職員會把它視為機構決定。人工智能會以具權威性的陳述方式草擬備忘錄，因為這正是該格式的特性。這種風格所暗示的權限與實際是否存在權限無關。討論變成決定、選項變成承諾、建議變成政策 — 不是因為任何人有此意圖，而是因為備忘錄格式暗示事情已定案。只檢查專業程度而不核查所述權限是否準確的審核者，可能無法察覺這點。

---

## 9. 其他需注意風險

- **[[風險分類#3.11 人工智能盲點 / 語境風險|人工智能盲點 / 語境風險]]：[[人工審核風險庫#4.22 用戶施壓導致偏移|用戶施壓導致偏移]]（中）** — 如使用者有把握地質疑謹慎答案，人工智能可能在沒有新可靠證據下軟化或推翻答案。同意使用者並不是核實。
- **[[風險分類#3.6 權限 / 範圍 / 承諾|權限 / 範圍 / 承諾]]：權限訊號誤讀（高）** — 人工智能可能不了解職員如何解讀階層、語氣、時機及隱含指示。備忘錄可能聽起來像實際未獲授權的決定、承諾、警告或管理層立場。
- **[[風險分類#3.4 私隱 / 機密性 / 資料邊界|私隱 / 機密性 / 資料邊界]]：機密內容外洩（高）** — 內部不代表低敏感度。備忘錄可能包含人力資源事項、財務資料或政策敏感內容。人工智能處理這些內容可能令資料超出原定邊界而外洩。
- **[[風險分類#3.4 私隱 / 機密性 / 資料邊界|私隱 / 機密性 / 資料邊界]]：發布範圍錯誤（中）** — 除非提供現行機構角色、分發規則或相關語境，否則不應假定人工智能知道適當的收件人。它可能產生範圍、語言或內容只適合某一受眾的文件，卻透過例行流程分發給更廣泛群組。
- **[[風險分類#3.3 語境 / 細微差別 / 壓縮|語境 / 細微差別 / 壓縮]]：語境差距 — 相關審核風險：[[人工審核風險庫#4.14 未成文語境差距|未成文語境差距]]（中）** — 人工智能不知道內部機構歷史、先前決定或人際互動。邏輯上看似正確的備忘錄，可能在具體情境中並不恰當。

## 11. 其他緩解措施

- 人工審核應由能批准範圍及承諾的人進行，而不是只由檢查拼寫或文法的人進行。
- 如敏感資料已輸入未獲批准的工具，審核輸出無法撤銷外洩。應按照私隱 / 事故處理流程升級處理。
- 人類審核者可能從記憶填補缺口；應保持來源文件可見，並明確標示不確定事項。
