# 草擬通訊

## 1. 這個應用案例是甚麼

如您希望人工智能協助草擬或改善日常機構通訊，包括電郵、通訊、公告、通知、簡報、活動通訊及社交媒體貼文，請使用本頁。

- 常見使用者：**教會、非牟利機構、中小企業**。
- 批准級別：**一般可批准使用**。
- 需要人工審核：**是 — 發送或發布前**。
- 使用人工智能輸出協助草擬或檢查工作。在負責人審核前，不要把它視為最終訊息。

---

## 2. 這可能造成甚麼代價

一則通訊可以聽起來親切、清晰並似乎可直接發送，卻帶有背景筆記中的舊日期、錯誤地點、錯誤姓名、缺乏支持的數字或非預期承諾。如審核者只檢查語氣及流暢度，訊息可能帶著影響出席、期望、信任或機構履行所述事項能力的錯誤傳達給讀者。

---

## 3. 如何審核這個輸出

批准人工智能輸出前，請使用以下檢查。不要只因輸出讀起來流暢便批准。

---

### 3.1 審核設定

1. 並排開啟來源材料及草稿。
2. 對照來源核對草稿中的每個日期、地點、姓名、數字、截止日期及連結 — 不要依賴記憶。
3. 檢查每項隱含承諾、許諾、道歉、批准、立場或截止日期。詢問機構是否確實已授權。
4. 以收件人角度閱讀草稿，而不只是以作者角度閱讀。作者會讀到自己原本想表達的意思；收件人只會讀到實際寫出的內容。
5. 檢查草稿是否包含或暗示不應分享的個人、機密、牧養、人力資源、財務、捐贈者、客戶、受益人或其他敏感資料。
6. 確認所使用的工具、帳戶及工作流程已獲批准處理該來源材料。

---

### 3.2 批准前 — 一項檢查

> **負責人是否已把這份草稿當作首次收到般閱讀 — 對照來源核對每個日期、姓名、數字、地點、截止日期、連結及隱含承諾，而不只是檢查整體語氣？**

---

### 3.3 針對風險的審核檢查

這些檢查把 [[人工審核風險庫]] 中的最低審核責任調整至本任務。

- **[[人工審核風險庫#4.1 低風險假設陷阱|低風險假設陷阱]]：** 對照已批准簡介及目前來源材料，而不是記憶，核對每個收件人姓名、日期、時間、地點、連結、聯絡資料、數字、截止日期、所要求行動及隱含許諾或承諾。更正或升級處理審核者無法確認的任何項目。
- **[[人工審核風險庫#4.7 提示詞過度信任|提示詞過度信任]]：** 獨立執行這則訊息所需的來源與事實、權限、私隱、收件人影響及批准檢查。不要因提示詞經過測試、獲批准、很詳細或看似已被遵從而批准訊息。
- **[[人工審核風險庫#4.10 指令漂移|指令漂移]]：** 每輪修訂後，把最終版本與原本目的、已批准事實、受眾、語氣、僅限來源邊界、私隱限制、禁止聲稱及批准邊界比較。恢復或升級處理任何被削弱或遺失的要求。
- **[[人工審核風險庫#4.13 人工智能盲點|人工智能盲點]]：** 輸出是否符合任務背後真實的人、真實情況、真實權限及真實後果，包括人工智能未獲告知的默會情境，以及無法完全化約為提示詞的生活經驗或專業判斷。
  - **就本應用案例而言：** 對照實際收件人、關係情境、時機、近期事件、發送者權限、機構立場，以及誤解訊息或據此行動的後果檢查草稿。
- **[[人工審核風險庫#4.16 受眾影響盲點|受眾影響盲點]]：** 檢查誰可能受影響，以及時機、語氣、披露、所要求行動或隱含壓力是否可能造成混淆、尷尬、排斥、困擾、信任損失或聲譽傷害。如影響敏感，使用了解受眾的審核者。

---

### 3.4 審核者決策

完成上述針對本任務的審核檢查後，使用 [[審核者決策卡]] 選擇一項結果：

- **原樣批准**
- **更正後批准**
- **停止並升級處理**

如審核者欠缺本任務所需的角色、證據、權限、能力、來源存取權、語境或已批准流程，不要批准輸出。

---

### 3.5 本任務的審核方法

以下審核指示已針對本任務調整。它們把 [[人工審核模式]] 中的可重用方法應用於這裏涉及的實際來源、決定、人士及後果。

- **一般輸出審核：** 檢查每則訊息是否達到所述目的、適合其渠道及受眾、包含所需行動，並維持在已批准長度及格式內。
  - 留意：缺少行動呼籲、受眾錯誤、格式漂移、下一步不清楚，或經修訂後已不再符合簡介的訊息。
  - 時間：發送或發布前。
  - 審核者：通訊負責人或負責發送者。

- **來源及事實核實：** 對照已批准來源核實每個姓名、日期、時間、地點、金額、連結、截止日期、容量及事實聲稱。
  - 留意：從記憶或舊活動材料複製的日常細節、虛構連結及缺乏支持的聲稱。
  - 時間：發送或發布前。
  - 審核者：來源負責人或能存取已批准事實的通訊審核者。

- **以人工判斷為本的審核：** 以實際收件人角度閱讀訊息，考慮時機、關係、近期事件、可能解讀及可能影響。
  - 留意：技術上清晰，但對實際收件人不敏感、令人不安、具誤導性或不恰當的措辭。
  - 時間：最終批准前。
  - 審核者：了解受眾的審核者、項目負責人，或了解收件人及目前語境的人。

- **範圍、權限及可行性審核：** 確認發送者獲授權作出訊息中的每項許諾、承諾、道歉、例外、政策陳述或行動呼籲。
  - 留意：邊界軟化、非官方機構聲音、無法履行的承諾或隱含批准。
  - 時間：發送或發布前。
  - 審核者：獲授權通訊負責人或決策負責人。

## 4. 何時應升級處理而不是批准

- 如輸出影響法律、人力資源、財務、安全保障、醫療、法規、對外或高影響決定，而審核者沒有確認安全使用所需的權限、能力、語境、來源存取權或已批准流程，應在使用前升級處理。
- 如聲稱影響法律、財務、牧養、神學、公眾或外部決策，而審核者未獲授權或不具能力確認，應升級處理。
- 如措辭涉及弱勢群體、文化、危機、投訴或公眾聲譽，而審核者欠缺確認安全使用所需的語境、權限或已批准流程，應升級處理。
- 如輸出可能約束機構、影響權利或義務，或看似正式批准，應升級處理。
- 如涉及機密資料、第三方系統、財務處理或自動化，而工具、帳戶、審核者或流程未獲批准作該用途，應在使用工具前升級處理。

## 5. 提示前

使用人工智能處理本任務前，先檢查以下基本事項：

- 目的清晰。
- 輸入不包含不應輸入工具的個人或機密資料。
- 工具、帳戶及工作流程已獲批准處理所使用的材料。
- 有負責人可在使用人工智能輸出前檢查它。
- 任務沒有要求人工智能作出決定、提供專業意見或充當最終權威。
- 確認本任務符合批准級別：**一般可批准使用**。
- 確認計劃中的審核者能完成所需人工審核：**是 — 發送或發布前**。

## 6. 人工智能盲點重點

**風險重點：** 受眾影響盲點

**提示詞重點：** 提示前，向人工智能提供預期受眾、渠道、目的、關係情境、已批准事實、敏感程度、發送者權限、時機，以及訊息不得暗示的事項。要求人工智能識別可能被誤解、比原意更強硬、暗示批准或權限、產生非預期承諾、顯得不敏感或令讀者混淆的措辭。

**人工審核重點：** 審核者應以實際收件人角度閱讀，而不只是以發送者角度。檢查真實受眾、時機、關係、機構立場及語境是否可能令訊息產生與發送者原意不同的效果。

**較深入的盲點審核：** 如訊息依賴未明說的關係歷史、近期事件、內部張力、受眾敏感度或某人可能的反應，請依循 [[如何使用本指南#6.1 Win.Win 人工智能盲點指南|Win.Win 人工智能盲點指南路徑]]。

**不要只依賴：** 清晰措辭本身。訊息在文法上可以很清楚，卻仍可能在社交、機構或實務上被誤解。

## 8. 主要風險

- **[[風險分類#3.1 準確性 / 幻覺|準確性 / 幻覺]]：[[人工審核風險庫#4.1 低風險假設陷阱|低風險假設陷阱]]（高）** — 草擬通訊、通知或公告感覺很例行。這種熟悉感本身就是風險。因為任務看似簡單，審核者可能只檢查明顯錯誤便迅速批准。通訊中具體而隱蔽的失敗 — 由貼上語境帶入的錯誤日期、並非原意的隱含承諾、由筆記帶入的個人細節 — 正是快速閱讀最容易漏過的問題。對機構造成最大損害的事件，往往不是來自人人都很小心的任務，而是來自沒有人預期會出問題的熟悉任務。


- **[[風險分類#3.1 準確性 / 幻覺|準確性 / 幻覺]]：[[人工審核風險庫#4.7 提示詞過度信任|提示詞過度信任]]（中）** — 使用者或審核者可能把設計良好、經測試或獲批准的提示詞，以及人工智能看似遵從提示詞，視為訊息安全、準確或可使用的證據。即使提示詞不能取代本任務所需的審核模式、核實、權限檢查或升級處理，所需審核仍可能因此被縮減或跳過。

## 9. 其他需注意風險

- **[[風險分類#3.11 人工智能盲點 / 語境風險|人工智能盲點 / 語境風險]]：[[人工審核風險庫#4.16 受眾影響盲點|受眾影響盲點]]（高）** — 人工智能可能寫出清晰有禮的訊息，卻忽略真實收件人會如何因時機、關係、近期事件或受眾期望而感受、誤解或反應。
- **[[風險分類#3.1 準確性 / 幻覺|準確性 / 幻覺]]：格式不一致（低）** — 人工智能不能可靠複製以往通訊的確切格式。審核者可能檢查內容但不檢查版面忠實度，令不同期數之間的格式漂移未被發現。
- **[[風險分類#3.1 準確性 / 幻覺|準確性 / 幻覺]]：工作階段記憶差距（中）** — 人工智能不會記得以往通訊或訊息。它無法識別不同期數之間的不一致，也無法察覺模式中斷。每個工作階段都由零開始。
- **[[風險分類#3.7 語氣 / 表述 / 文化敏感度|語氣 / 表述 / 文化敏感度]]：語氣漂移（中）** — 人工智能可能逐步把語氣移離原本要求。語氣漂移比事實錯誤更難察覺，因為它主觀而且漸進。輸出可能錯誤代表機構聲音。
- **[[風險分類#3.6 權限 / 範圍 / 承諾|權限 / 範圍 / 承諾]]：邊界軟化（高）** — 人工智能可能暗示承諾，或軟化原本筆記並未明確意圖放寬的界線。輸出可能通過事實核對，卻作出未經授權的機構承諾。
- **牧養 / 神學 / 聖經：提示詞中的敏感資料（高）** — 使用者可能把敏感成員資料、機密細節或牧養內容貼入提示詞。提示詞模式本身無法防止這種情況 — 這是使用者紀律失效，而不是人工智能輸出失效。
- **[[風險分類#3.5 工具 / 安全 / 流程管治|工具 / 安全 / 流程管治]]：影子人工智能風險（高）** — 所使用的工具可能是個人消費者帳戶，而不是已批准的機構帳戶。消費者帳戶未必具有機構的資料保護設定、審核工作流程或退出模型訓練保障。
- **[[風險分類#3.6 權限 / 範圍 / 承諾|權限 / 範圍 / 承諾]]：未經授權代表機構發聲（高）** — 對公開貼文、正式通知或社交媒體而言，人工智能可能產生聽起來具權威、並代表機構對未經領導層批准事項立場的內容。讀者無法分辨人工智能草擬措辭與領導層批准措辭。
- **[[風險分類#3.3 語境 / 細微差別 / 壓縮|語境 / 細微差別 / 壓縮]]：[[人工審核風險庫#4.10 指令漂移|指令漂移]]（中）** — 在反覆修訂期間，即使人工智能最初已確認指示，也可能逐步偏離原本邊界、語氣、僅限來源規則或批准限制。最終訊息必須對照原本指示檢查，而不只是對照最新草稿。

## 10. 要加入的提示詞強化

先從 Win.Win 人工智能必備的基礎提示詞模式開始。以下附加項已針對本任務調整。

只使用與實際情況相符的列。不要只因某項控制出現在 [[提示詞強化模式]] 便加入無關控制。對於主要須透過人工審核、已批准工具、專業檢查、其他緩解措施或升級處理的風險，不要建立提示詞附加項。

把來源材料、筆記、政策摘錄、數字及文件放在基礎提示詞最後的 **內容** 部分。

## 12. 其他緩解措施

- 人工審核可降低風險，但不能保證準確。保留記錄並使用已批准工具。
- 審核的強度取決於所核對的來源。對法律、醫療、財務或法規聲稱，應升級至合資格審核。
- 內容審核無法修正錯誤的工具、帳戶或資料流程。使用輸出前先修正流程。
- 人工審核應由能批准範圍及承諾的人進行，而不是只由檢查拼寫或文法的人進行。
- 如通訊依賴近期事件、本地歷史、內部張力或受眾敏感度，使用 **Win.Win 人工智能盲點指南**進行更深入的盲點識別及控制選擇。只披露或擷取目前任務所需的語境。在合適情況下使用安全轉換或僅由人處理；如語境不適合，應停止、升級處理，或不要使用或記錄。把任何記錄或保存視為獨立的受管治決定。
